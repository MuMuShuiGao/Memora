# ADR-0009：手机经公网 IP + 自签 HTTPS 直连服务端

> 状态：生效中
> 摘要：服务端在公网 IP 上以自签证书提供 HTTPS，证书内置进 APK 做校验；安全组只放行这一个业务端口
> 日期：2026-11-24 ｜ 关联：[0001-server-owned-data-on-lan.md](0001-server-owned-data-on-lan.md)、[0002-single-user-passphrase.md](0002-single-user-passphrase.md)、[0008-native-kotlin-client.md](0008-native-kotlin-client.md)

## 决策

服务端监听在公网可达的地址上，只用 HTTPS，证书自签、公钥内置进 APK 并做校验（不做"忽略证书错误"的开关）。云厂商的安全组只放行这一个业务端口，其余入站保持现状。IP 值与端口值不入档，见 [../writing-rules.md](../writing-rules.md) §9。手机在蜂窝网络和任意外部 WiFi 下都能读写，ADR-0001 的验收线由此变得可执行。

## 背景

ADR-0001 写的是"服务器只在私网可达，手机离开这个网络就用不了应用"。实测这台机器是云上主机（厂商与区域按 §9 不入档），网卡上只有 VPC 内网地址（实测），手机永远进不到那个网段——按 0001 的原话，FR-01"在第二台设备上看到同一条记录"根本没法验收。同一轮实测：metadata 的公网地址字段有值，且与出网探测看到的地址一致；入向也是通的（此刻有从公网发起的 SSH 会话），本机防火墙没有拦截入站（ufw inactive、INPUT 策略 ACCEPT，实测）。0001 否掉公网那条给的理由是"手上没有域名"——域名这次确认仍然没有，但公网 IP 明摆着存在，两者不是一回事。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| **公网 IP + 自签 HTTPS，证书打进 APK** | 证书到期要换并重装 APK；公网 IP 变了同样要重装；公网上多一个监听端口 | **采纳** |
| Tailscale / WireGuard 造一个私有网 | 手机要常驻一个第三方 app，服务端多一个进程并依赖第三方控制面；每次记录前先确认隧道在不在 | 否决：安全上是最优解，但把"掏出来就记一笔"变成"先看 VPN 连上没"，天天多这一步；需求方选了直连 |
| 明文 HTTP 直连 IP:端口 | 口令和记录原文在城域网与运营商链路上裸跑；公网非标端口几小时内会被扫描器找到 | 否决：ADR-0005 明确不做脱敏，记录里允许出现手机号、密钥类原文，明文传输等于把它们发出去；省下的只有一次证书生成 |
| 域名 + CA 证书 + 反向代理 | 要拿到域名并完成 ICP 备案（内地服务器 80/443 面向公众需要），还要长期维护续期与反代配置 | 否决：本次确认手上没有域名；为一个人用的工具背上一条备案和一条续期义务，不成比例 |

## 影响

- **得到**：手机在任何网络可用，FR-01 真能验收；链路加密，ADR-0002 那个唯一口令不再明文出现在网络上。
- **付出**：暴露面从"仅 VPC 内网"变成一个公网端口；自签证书不在系统信任链里，**校验必须由客户端自己做**，否则中间人可以换一张证书而客户端毫无察觉，等于没加密；证书到期与 IP 变更都要重装 APK；公网流量按服务器带宽计费。
- **返工点**：日后拿到域名换 CA 证书，只改服务端证书来源和 APK 里那条校验配置，业务接口不动；想转 VPN，把服务端退回只监听内网、安全组收回全部入站，客户端换个地址即可——都不会推翻数据归属结论。
- **连带决定**：ADR-0001 被本条取代的只有"网络可达方式"这一半，其"服务器为唯一权威副本"仍生效（按 [../writing-rules.md](../writing-rules.md) §3 旧正文不改，取代范围记在这里）。口令成为公网暴露下的唯一防线，因此服务端必须只存口令的哈希、且支持改口令后旧客户端立刻失效；管理面板的端口不得对公网放开。

## 复查条件

出现以下情况时重新评估本决策：

- 拿到域名且愿意备案 → 换成 CA 证书，本条的证书管理部分作废
- 公网 IP 变更频繁到重装 APK 成为负担 → 转 Tailscale 或域名
- 访问日志出现同一来源的连续口令失败 → 加限速/锁定，或直接转 VPN
- 需要第二个人或第二套部署访问同一批数据 → 认证模型整条重开（ADR-0002）

## 替代成本参考

Android 的 network security config 原生支持内置 CA 与证书锁定，而客户端本来就是自签 APK（ADR-0008），多打包一张证书不改变现有分发方式。同类自用服务的常见做法是 smallstep step-ca 自管签发，或直接用手机端 VPN 客户端换掉整个入站暴露面。
