# ADR-0004：报表同时支持手动触发与服务端定时生成，结果存为快照

> 状态：生效中
> 摘要：定时负责到点归档，手动负责重算与看未结束的周期；每个周期只保留一份当前报表
> 日期：2026-11-24 ｜ 关联：[../projectneed.md](../projectneed.md) FR-04、FR-05、[0003](0003-external-llm-generation.md)

## 决策

两条触发路径并存。服务端按自然周期到点自动生成上一周期的报表，不需要任何设备参与；客户端另外提供"现在生成"，可用于本周/本月这类尚未结束的区间，也可用于改完记录后重算。生成结果作为快照保存，之后原始记录被修改或删除都不影响它。一个周期同时只有一份当前报表，重新生成即替换。

## 背景

对齐时需求方在"只手动 / 只定时 / 都要"里选了"都要"。ADR-0001 已确定报表只能由服务端生成，因此定时这一半不需要推送通道，只要一个跑在服务端的调度。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| **定时 + 手动双触发** | 要引入调度，并回答"服务中断错过时刻怎么办"；同一周期可能被人工重算覆盖 | **采纳** |
| 只手动 | 忘了点就没有这一周的归档；每次都要等人打开应用 | 否决：需求方要的是"打开就有"。而且只手动会让"这周到底写过什么"依赖人记得去问 |
| 只定时 | 周中想看一眼、或补记了几条之后想重算，都做不到 | 否决：没有人工入口，生成失败时也就没有重试的地方，失败只能靠看日志发现 |
| 结果不落库，每次打开现场生成 | 每次打开都花一次调用费用与等待；内容会随模型抖动而变，昨天的周报今天再打开不是同一份 | 否决：需求 §4 把"重复打开内容一致"写成了验收线，现场生成做不到；也无法证明"报表没被后来的修改影响" |

## 影响

- **得到**：定时保证不漏归档，手动保证能重算和随时看未结束的周期；快照落库后报表成为独立可读的产物，模型挂了也不影响历史报表（呼应需求 §5 第 2 条）。
- **付出**：需要持久化"某周期已生成/生成失败"的状态，否则 FR-05 的"不静默缺失"无法验收；调度失败要与模型调用失败区分处理；同一周期替换旧版意味着"改完重算"会覆盖之前的产物。
- **返工点**：若改成保留历史版本——报表要加版本维度，列表和查看界面要选默认展示哪一版。若退回只手动——去掉调度即可，数据层不用动。
- **连带决定**：周期口径必须固定为自然周/自然月（已在需求 §4 定义），否则定时任务的触发时刻没有意义。

## 复查条件

出现以下情况时重新评估本决策：

- 定时生成的质量差到每次都得手动重算一遍——那"自动归档"就没有价值，应退回只手动
- 需要把报表推送到邮箱/IM，此时定时这一半要额外处理发送失败与去重
- 需要同时出多种口径的报表（如按项目、按标签），此时"一个周期一份当前报表"这个约束会先撑不住
