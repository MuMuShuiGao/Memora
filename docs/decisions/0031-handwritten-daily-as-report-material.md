# ADR-0031：手写日报作为周报的第四路素材

> 状态：生效中
> 摘要：新增 `dailies` 表，一天一条、本人手写优先级/完成/卡点三段；按日期归属周月，作为周报月报可信度最高的素材；不生成日报快照、不新建优先级对象、不提醒不发送
> 日期：2026-11-28 ｜ 关联：[../projectneed.md](../projectneed.md) FR-18、[memo-and-report.md](../design/memo-and-report.md)、[android-client.md](../design/android-client.md)、[0014](0014-todo-tasks-with-priority.md)、[0030](0030-task-stages-as-report-points.md)

## 决策

新增 `dailies` 表：一天一条，字段是三段纯文本——优先级、今天做成了什么、卡点与没做完的。日报由本人手写，**不由模型生成、不落 `reports` 表、没有 `kind='day'`**。写作入口是主屏抽屉第二项「日报」，默认今天，可向前补记；优先级一键从当前待办的未完成序列前五抄入文本，完成一键从当天勾掉的待办与阶段抄入，抄完即普通文本，可删可改，之后不再与待办联动。生成周报/月报时，日报按 `entry_day` 落进周期，作为第四路素材，语义是「本人当晚亲笔写的总结」：可信度最高，日报已覆盖的事不与其他素材重复计，日报里的优先级是计划不是完成，卡点直接进「风险与需要确认」。日报不提醒、不打卡、不对接外部汇报系统。

## 背景

- 需求方 2026-11-28 明确：要的是自己每天写一条日报，方便周末汇总写周报，不是让模型再生成一份日报告。
- 现有周报素材三路：按创建时间归周的记录、按勾掉时刻归周的待办与阶段（ADR-0014、ADR-0030）。记录是白天的碎片，缺少“当天收束”的一层；周末写周报仍要在零碎记录里回忆。
- 记录不能替代日报：记录按 `created_at` 归周，周六早上补写周五的日报会落到下一周；记录也没有“一天一条”和“本人总结”这个语义，提示词无法把它与随手想法区分开。
- 需求方同时定死两条：优先级从待办取，不新建优先级对象；日报不能复杂，否则自己都懒得填。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 独立 `dailies` 表，三段手写文本，进周报素材 | 一张表、两个接口、一个屏、第四路素材与提示词规则 | **采纳** |
| 日报作为 `reports` 的第三种 kind，由模型生成 | 不新增表 | 否决：需求方要自己写；模型的“明日计划/风险”没有数据源，只能编造或写“无”；每天一次模型调用换来一份比周报更薄的产物 |
| 用记录 + 固定模板，不建表 | 零服务端改动 | 否决：记录按创建时间归周，补记会串周；无法保证一天一条；提示词分不出“本人总结”与随手想法，日报的核心价值丢失 |
| 日报里新建优先级字段或引用待办 id | 优先级更结构化 | 否决：等于给待办顺序再造一份镜像，拖拽/删除后必然漂移；需求方明确要求“从待办取、不新建”，抄成文本已够周末汇总 |
| 只显示当前待办、不落日报文本 | 填得更省 | 否决：回看旧日报看到的是现在的优先级；周末汇总时用不上“那天当时排在前面的几件事” |
| 模型把日报润色成正式日报 | 措辞更整齐 | 否决：日报是本人亲笔的素材，润色会引入模型改写的风险；且让日报依赖 `MEMORA_LLM_API_KEY`，key 没填时日报不能写 |
| 日报自动提醒、连续打卡、对外发送 | 更像工作日报工具 | 否决：需求方只要自己记录，提醒与打卡会制造负担；外发需要收件人与失败处理，超出单机自用 |

## 影响

- **得到**：每天一两分钟留下“结果、原因、卡点”这层周报最缺的素材；补记按日期归周，不会串周；周报提示词有了最高可信度的一路输入；日报屏不依赖模型，key 没填也能写。
- **付出**：周报/月报提示词与 `source_count` 多一路，需写清“日报优先级是计划、不可当完成”；日报与记录存在内容重叠，靠提示词去重规则兜住；抽屉从五项变六项，切区块多一项。
- **返工点**：若日报要改成结构化优先级引用，需加关联表并重写日报屏与提示词；若日报要对外发送，需要新增投递渠道、失败重试与格式转换。
- **连带决定**：日报编辑旧日期不迁移周期；三节全空视为没有这条，不进素材也不触发补跑；界面不允许选未来日期；不提供删除接口，保存全空即等于清掉素材；日报不替换记录，记录仍负责白天的碎片。

## 复查条件

出现以下情况时重新评估本决策：

- 连续一个月日报使用频率低于每周两次——说明填写成本仍高于收益，重估三段式与带入按钮。
- 日报内容长期与记录/待办高度重复，周报没有变好——重估“日报作为素材”的价值，考虑只保留周报自动生成。
- 需求方要求日报结构化到“每条优先级对应某个待办”或要对外提交——那是另一个对象，需重开设计与 ADR。
- 日报需要提醒、模板市场或多套模板——与“不能复杂”冲突，先重估需求再动功能。

## 替代成本参考

职场日报里最经得住用的是 3P（Progress / Plans / Problems）：写完成、写计划、写卡点，每节一两行，不记工时、不写流水。iDoneThis、Geekbot 这类工具也是“到点发问、人回答”，而不是纯自动摘要。个人日记类产品（Day One 等）则只保日期与正文，不做结构化。本条取 3P 的三段结构，但不引入任何团队协作或投递能力。
