# ADR-0014：待办独立成表，完成时刻决定它进哪一期报表

> 状态：生效中
> 摘要：待办是与记录平行的第二类对象，有自己的表和接口；只有"在本周期内被勾掉"的待办才进报表，未完成的一律不进
> 日期：2026-11-26 ｜ 关联：[design/memo-and-report.md](../design/memo-and-report.md)、[design/android-client.md](../design/android-client.md)

## 决策

新增一张 `tasks` 表和一套 `/v1/tasks` 接口，与 `notes` 互不相干：待办有优先级顺序、有完成态，记录没有。报表取数从"该周期的全部记录"变成两路——记录仍按创建时间的归属周/月，待办按**完成时刻 `done_at` 落在周期内**取，未勾掉的待办一条都不进。勾掉即离开当前清单、沉到已完成区，第 6 名自动顶上。

本条推翻 [projectneed.md §2](../projectneed.md) 原本写死的"不做：待办勾选、完成状态"，那张表已同步改掉。

## 背景

需求方要一个真正能用的待办：勾一下就完成、按优先级只露前五条、其余折叠、拖拽调序。原表否掉它的理由不是实现不了，而是**口径**："一旦条目有完成状态，'这周做了什么'就要在已完成和未完成之间重新定义口径，报表逻辑整个要变"。这个顾虑仍然成立，所以本 ADR 的核心不是"做不做勾选"，而是先把新口径定死，再动代码。

现有资产要一并考虑：`notes` 列表按 `created_at` 倒序 + 关键词过滤 + 游标分页，服务端 33 个单测、冒烟 70 项，全部建立在这套排序语义上。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 独立 `tasks` 表 + `/v1/tasks` | 多一张表、五个接口，录入时分得清"记一条"和"加待办" | **采纳** |
| 复用 `notes` 加 `done` / `rank` 两列 | 同一批行要同时支持"按时间倒序"和"按优先级拖拽序"两种排序，列表查询、分页游标、报表取数全部分支 | 否决：流水和清单是两种语义，混在一张表里会让现有 33 个单测的断言全部变成条件式的，回归看不出边界 |
| 待办只存手机本地 | 不用动服务端，一两天出 | 否决：直接违背 ADR-0001"业务数据只在服务端"与需求 §5"换机后能完整找回"；且本地待办永远进不了报表，这条需求等于只做一半 |
| 优先级用可排序分数（1000、2000…） | 插入不用重排全表 | 否决：拖拽是"整列重排"而不是"中间插一条"，分数法在拖完之后仍然要重编号；且 REAL 分数会随反复插入耗尽间隙，换来的是一个看不见的定时炸弹 |
| 报表把待办与记录混成一段喂给模型 | 少一个提示词分段 | 否决：模型分不清"我记下的想法"和"我勾掉的事项"，需求 §5 第 4 条禁止编造，来源混起来就没法归因 |
| 引入第三方拖拽排序库 | 手势代码少写 | 否决：ADR-0010 已把客户端依赖钉死在 OkHttp + kotlinx.serialization；待办一屏最多十几行，手写一个竖直拖拽够用 |

## 影响

- **得到**：待办是真待办（换机找得回、能进报表），记录侧一行代码不改，两套排序语义互不污染。
- **付出**：`source_count` 的含义变了——从"该周期记录条数"变成"喂给模型的素材条数（记录 + 本周期完成的待办）"，这个口径必须写进设计文档，否则 FR-08 的验收线读起来是错的。另外"记一条"和"加待办"成了两个入口，用户得自己选。
- **返工点**：想并回一张表要重建 `notes` 的排序查询、删掉 `tasks` 表并写一次数据迁移，报表取数改回单路；服务端 `store` / `api` / `report` 三块和安卓端一个 Screen 都要动。
- **连带决定**：取消勾选回来的待办排到队尾（它刚被处理过，不是当前焦点）；新建待办排到队首（刚想起来的事正因为要先做才会去记，排到队尾等于加完看不见）；拖拽一次提交整列顺序而非单条改动，避免"拖一次发 N 个请求、失败后顺序各说各话"。

## 复查条件

出现以下情况时重新评估本决策：

- 待办需要截止日期、重复、子任务中的任意一项——那时它已经是任务管理系统，不该再挂在备忘录上。
- 一个人以上使用，或出现第二个客户端同时编辑顺序（ADR-0002 失效）。
- 未勾选的待办长期堆积且需求方要求在报表里体现"还没做完"，本条"未完成不进报表"的口径需要重开。

## 替代成本参考

Things、Todoist 这类应用把"待办"和"笔记/日记"当成两个顶层对象，理由相同：完成态和排序语义无法与流水记录共用一套。本条与它们同向，代价是多一个入口。
