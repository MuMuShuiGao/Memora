# ADR-0028：主屏导航改左侧目录抽屉

> 状态：生效中
> 摘要：五个区块收进左侧抽屉，打开仍直接落待办；撤掉顶部页签行，不引导航库；代价是切区块多一次点击
> 日期：2026-11-27 ｜ 关联：[design/android-client.md](../design/android-client.md)

## 决策

主屏的区块导航从顶部页签行改为左侧抽屉（Material3 `ModalNavigationDrawer`，抽屉内容自绘成纸色目录）：待办、日历、记录、读书、报表五个区块。打开 App 仍直接落在待办；抽屉只在主屏出现，编辑页、更新页和连接页没有。区块状态仍用 `AppRoot` 里的一个字符串状态机，`rememberSaveableStateHolder` 按区块名保住各自的选中日、展开态与草稿。

## 背景

- 需求方要新增「读书」区块，并明确要左侧边栏，理由是以后还可能继续加功能。
- 原来顶部页签行已有四个；底部栏/页签的常规上限是五，读书正好占满，下一次再加就没有位置。
- 客户端不引导航库（[ADR-0010](0010-minimal-android-deps.md)），页面切换一直是 `AppRoot` 里的一个字符串状态。
- 视觉约束「编辑部案头」（[ADR-0013](0013-editorial-desk-visual.md)）要求导航不引入 Material 的默认药丸底或卡片。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 左侧抽屉：菜单图标 + 左缘滑动打开 | 切区块两次点击；抽屉要自绘一套目录样式 | **采纳** |
| 底部五页签 | 正好占满上限，下一块就要重做；中文标签在第五档被挤窄 | 否决：需求方明确要侧边栏，这条路没有余量 |
| 顶部页签行 + 「更多」入口 | 未来区块藏进二级菜单，点两次还不一定看得见 | 否决：等于把以后要加的东西做成隐藏功能 |
| 常驻窄侧栏（navigation rail） | 常驻占掉约 80dp 正文宽度，每一屏都在付这笔账 | 否决：手机上正文宽度比常驻导航值钱 |
| 引 Navigation Compose | 多一个依赖，返回栈、路由参数、目的地序列化都要多写一层 | 否决：ADR-0010 的最小依赖口径；本应用没有深链与多栈需求 |

## 影响

- **得到**：区块数量不再受底部栏上限约束；加新区块只改 `App.kt` 的区块表与抽屉。
- **付出**：主屏切区块从一次点击变两次（开抽屉 + 选中）；返回键要先关抽屉；`Masthead` 从页签行变成菜单图标 + 区块名。
- **返工点**：抽屉只包在 `Workspace` 一层，若改回底部栏或常驻侧栏，只动 `App.kt` 与 `Components.kt` 的图标，业务屏不受影响。
- **连带决定**：页签状态保留（[ADR-0024](0024-per-row-toggle-and-state-keeping.md)）从「四页签」扩到「五区块」，键仍是区块名；抽屉不放在编辑页与更新页，避免未保存的输入被切走。

## 复查条件

出现以下情况时重新评估本决策：

- 区块数量超过 7 个，或需要深链、跨区块返回栈、多窗口布局。
- 实际使用后「开抽屉」明显比顶部页签慢，且需求方愿意用回底部栏。
- 抽屉的自绘样式需要为它单独维护超过一屏的代码，说明该换成现成导航容器。

## 替代成本参考

单用户工具类 App 在区块超过 5 个后普遍转抽屉或侧栏（记账、笔记类都是这个路数）；左缘滑动打开抽屉是 Android 用户的既有肌肉记忆，Material3 也内置了手势与遮罩，自绘只花在样式上。
