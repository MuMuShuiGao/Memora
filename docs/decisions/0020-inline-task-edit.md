# ADR-0020：待办正文在行内改

> 状态：生效中
> 摘要：待办正文点开就在这一行里改：回车保存、返回放弃，只发 `{body}`；名次、完成态、勾掉时刻与报表归属都不动
> 日期：2026-11-27 ｜ 关联：[ADR-0014](0014-todo-tasks-with-priority.md)、[ADR-0017](0017-drawn-line-icons.md)、[design/android-client.md](../design/android-client.md)、[design/memo-and-report.md](../design/memo-and-report.md)

## 决策

待办行里的正文是可点的：点一下，这一行原地换成单行输入框，预填原文并自动聚焦；回车（IME 的完成键）保存，系统返回键放弃，点另一条待办的正文则先保存当前这条、再进入那一条。保存只发 `PATCH /v1/tasks/{id} {body}`——正文之外一概不动：`rank` 不重编、`done` / `done_at` / 归属列原样，已勾掉的待办也能改字，改完仍归它当初勾掉的那个周期。空白正文按放弃处理，不删条；写失败走待办写操作已有的"提示 + 回滚重拉"路径。

编辑中的那一行收起删除图标与拖拽把手，只留勾选框；切页签等于放弃未保存的修改。本决策不推翻 [ADR-0014](0014-todo-tasks-with-priority.md)（待办仍是一句话、独立成表），也不改 [ADR-0017](0017-drawn-line-icons.md) 的图标语言——这条新路一个图标都没加。

## 背景

需求方 2026-11-27 提出"待办要可编辑"。此前录入只支持加、勾、删、拖，写错一个字只能删掉重录，重录会丢掉它原来的名次；已勾掉的重录还会把完成时刻改成当下，等于把它挪进另一期报表。

约束来自既有定论：待办是一句话（ADR-0014 的边界），ADR-0014 与客户端设计已经把"为待办开一屏"否掉过一次——录入走屏顶单行框，不进整屏编辑器。编辑没有理由比录入更重。服务端当时已经支持 `PATCH {body}`（`store.UpdateTaskBody` 只改正文与 `updated_at`），缺的只是客户端入口。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 行内单行编辑（本决策） | 行高在编辑时变化；未保存的内容不跨页签、不跨进程保留 | **采纳**：零新增控件，点正文就是最自然的目标；与"待办是一句话"和录入行同一套 `UnderlineField` |
| 复用整屏 `EditorScreen` | 多一层导航；待办要绕开那屏的草稿、计数与页边线 | 否决：为一句待办开一屏，和 ADR-0014 已定的"待办不开整屏编辑器"自相矛盾；编辑器那套是记录的语言（多行草稿、n/2000），挂到待办上还要再分一套分支 |
| 弹窗里放单行输入 | 实现最省事 | 否决：全 App 没有弹窗，提醒与错误都走行内 `Notice`；弹窗遮住列表上下文，改一条待办时看不到它前后的名次 |
| 每行加一枚铅笔图标 | 入口显式，不与点击正文抢手势 | 否决：这一行已经有勾选框、删除、拖拽把手三个热区，ADR-0017 刚从行内收走文字、把宽度还给正文；再加第四个图标，正文只剩两三个字。点正文本身没有别的手势占用 |
| 长按正文进入编辑 | 防误触，点击可留给别的动作 | 否决：发现性差，界面上没有任何提示；单行文本的长按还和系统的选择/复制手势冲突 |
| 每行常驻输入框 | 不用切换状态 | 否决：十几行同时是输入框，滚动与聚焦互相打架，键盘会在滑动时被意外拉起 |

## 影响

- **得到**：改错字不再删了重录，名次保留；已勾掉的待办改字后报表归属不变。
- **付出**：编辑态活在行内，行高会变（输入框比两行正文矮）；未保存内容不落草稿、不留到切页签之后——这是与记录编辑页的有意差别，一句话的代价用不着那套机制。
- **返工点**：想改成整屏编辑，只需在 `TasksScreen.kt` 把行内入口改成一个回调、由 `App.kt` 复用 `EditorScreen`；服务端一行不用动。
- **连带决定**：改正文不参与待办的 `busy` 互斥——它不碰顺序，和勾选/拖拽/新建可以并发；失败时仍统一走 `reload++`，以服务端为准。`MemoApi.updateTaskBody()` 从"写好没用的函数"变成唯一调用点。

## 复查条件

- 需求方开始记多行待办，或要求在待办里写备注、截止日期——行内单行装不下时重估（那也已经触发 ADR-0014 的复查条件）
- 真手指在行内编辑与拖拽把手之间反复误触，说明两个手势的边界要重划
- 出现第二个客户端同时编辑同一条待办（ADR-0002 失效），"后写覆盖先写"需要重新定口径

## 替代成本参考

Things、Todoist 的行内改名同样是点正文直接改、回车落定，不弹窗也不跳页；它们把整屏编辑留给带备注、日期、清单的多字段任务。本条与它们同向：只有一个字段的对象，编辑入口就该只有一次点击。
