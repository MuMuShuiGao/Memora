# ADR-0003：周报月报由外部大模型 API 生成，密钥留在服务端

> 状态：生效中
> 摘要：需求方自带 API key，服务端调用一个对话补全接口生成报表；不在服务器本地跑模型，也不用模板拼接
> 日期：2026-11-24 ｜ 关联：[../projectneed.md](../projectneed.md) FR-04、[0001](0001-server-owned-data-on-lan.md)

## 决策

报表正文由外部大模型 API 生成：服务端把某个周期内的纯文字记录交给模型，拿回一段可以复制就交出去的正文。调用方式抽象到"一个对话补全接口 + 一份提示词"，供应商和密钥写在服务端配置里，由需求方自己提供。模型调用只发生在服务端，绝不在安卓端。

## 背景

需求的核心动作是把碎片合成一段人话。服务器可用资源实测为 4 核、总内存约 3GB；机器上没有查到任何可用的模型 API 密钥环境变量。需求方确认自己有 key（通义/DeepSeek/OpenAI 一类）。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| **外部 API + 需求方自带 key，服务端调用** | 依赖第三方的可用性与计费；原文要发给外部服务；换供应商时输出质量要重新验一遍 | **采纳** |
| 服务器本地部署开源模型（Ollama 一类） | 3GB 总内存（实测）放不下能产出可用中文总结的规模；4 核上生成一份周报要按分钟计 | 否决：硬件条件不允许。而报表质量就是这个项目唯一成败标准，模型能力打折等于项目本身打折 |
| 不用模型，按时间和关键词把记录拼接成模板文本 | 零依赖、零成本、结果完全确定 | 否决：拼接只能给出清单，给不出"把三句碎片合成一段说明做了什么"。而这恰恰是唯一要解决的问题——否掉它等于否掉需求 |
| 在安卓端直接调模型 | key 要打进 APK 或写进手机配置，泄露面从一台机器变成一台随身设备 | 否决：定时生成必须在手机不在场时也能跑（ADR-0004），密钥放手机端连这个前提都不成立 |

## 影响

- **得到**：报表质量取决于模型而非本机硬件；换供应商只动配置与提示词；定时任务在服务端跑，与设备是否在线无关。
- **付出**：模型服务不可用时无法生成新报表（但已有记录和已生成报表必须仍可读——这条已写进需求 §5 第 2 条）；有 API 费用；内容出境给第三方。
- **返工点**：换供应商——改配置项、重新校准提示词、拿同一批记录对比输出。要加本地模型——需要先把"生成能力"做成可插拔的一层；目前只有一处调用，不做这层抽象。
- **连带决定**：提示词与"该周期有哪些记录"这件事都归服务端，客户端只负责触发和展示结果。

## 复查条件

出现以下情况时重新评估本决策：

- 记录内容开始包含不宜发给外部服务的信息
- 部署环境变成必须完全离线
- 出现"生成结果反复编造记录里没有的东西"（见需求 §5 第 4 条）且换提示词无效——那时要重估的是"靠模型自由发挥"这个前提，而不是供应商

## 替代成本参考

同类"笔记自动汇总"产品（含 Notion AI、Obsidian 的社区插件）走的都是外部 API + 服务端或桌面端持密钥这条路。差异只在密钥放哪：面向多用户的产品放服务端，与本项目一致。
