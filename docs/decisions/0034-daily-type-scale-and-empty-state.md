# ADR-0034：日报字阶收束与空表单占位对齐

> 状态：生效中
> 摘要：日报正文降到 16/27、小节标题改为 14/20 半粗无衬线、空表单只留两行并把提示贴到第一行；两处抄入改叫「记上」，全局 `Theme.kt` 不动，仅多行框空态跟着对齐
> 日期：2026-11-28 ｜ 关联：[0032](0032-daily-autosave-and-calendar-lookup.md)、[0031](0031-handwritten-daily-as-report-material.md)、[0013](0013-editorial-desk-visual.md)、[../design/android-client.md](../design/android-client.md)

## 决策

日报屏只改三件互相咬合的事，其余版式不动（ADR-0013、ADR-0031）。

- **字阶**：日期头保持 21/30 衬线；三段的小节标题改为 14/20 无衬线半粗；正文由 17/30 收到 16/27 衬线；提示保持 13/20 无衬线；朱色抄入动作 13/18。全局 `Theme.kt` 不动，只在这块屏按样式副本取值。
- **空表单**：多行输入框的占位提示贴第一行顶对齐，和光标同一条基线；日报每段最少留 2 行（仍随输入长到 8 行）。单行框与 `minLines = 1` 的框保持原来的垂直居中。
- **文案**：「从待办抄五条」改「记上五条待办」，「抄今天勾掉的」改「记上今天做完的」，「写结果就行，不用交代过程」收成「写结果就好」。动作只补尚未出现的行、抄完即断链的语义不变。

`UnderlineField` 的对齐改动按 `!singleLine && minLines > 1` 生效，读书页那份 4 行心得框同样换成顶对齐；单行框与待办行内编辑不受影响。

## 背景

- 需求方 2026-11-28 拿日报截图反馈：正文和小节标题只差 2sp，打开像一整页大号正文，标题压不住；空表单里提示浮在输入线中部、光标悬在提示上方，像两行没对齐的小字。
- 现有日报正文 17/30 与待办正文同值（ADR-0032 定），但待办是「一行一句」的清单，日报是成段手写；同样的字号在成段文字里显得更大更松。30sp 行高又把三段撑得很长。
- 小节标题 15/21 仍是无衬线，但只比正文小 2sp、字重 Medium，衬线的 x 高度又比无衬线显眼，层级实际由颜色而不是字号承担。
- 占位提示在 `decorationBox` 的 `Box` 里垂直居中；`minLines = 3` 时提示落在第二行，光标在第一行，空表单看起来像提示线漂在字上。
- 字号 1.3x/2.0x 的系统放大仍要成立：顶对齐与两行起排都能随输入向下长。
- 需求方把取舍交给实现方，要求从产品经理与用户视角把「美感」落成可执行的数，不要只换颜色。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 日报局部字阶 16/27 + 14/20 半粗标题 + 两行空态 + 「记上」文案 | 日报与待办正文不再同号；多一套屏内样式 | **采纳** |
| 维持 17/30，只把标题加大到 18/24 | 改动最小 | 否决：标题一大，正文与提示之间的空隙更挤；同样字号下成段文字仍显大，1.3x 时更明显 |
| 正文直接用 `bodyMedium` 15/26 | 复用现有字阶，不新增数 | 否决：同一句待办在待办页 17/30、在日报里 15/26，切一次区块字就「缩水」；日报是手写素材，不该比清单低一档。留作一周后仍嫌大时的退路 |
| 全局把 `Theme.kt` 的 `bodyLarge` 改成 16/27 | 一次统一 | 否决：牵动记录、报表、待办等屏的换行与密度，ADR-0013 的全局字阶要整轮复查；这次的问题只在日报的成段排版 |
| 标题维持 15/21，只把颜色调淡或加间距 | 不动字号 | 否决：层级差靠颜色承担时，标题和提示会混成同一种灰字；字号与字重才是标题的本分 |
| 占位提示继续居中，只把 `minLines` 降到 2 | 改动仅在日报 | 否决：两行时居中仍与第一行光标错半行；提示是「第一行写什么」的引子，应该和第一行同基线 |
| 给 `UnderlineField` 加专用开关，只让日报顶对齐 | 其它屏零风险 | 暂缓：读书心得框也是多行，提示同样漂在中间；按行数判断比再加参数更省。出现反例再收回开关 |
| 保留「抄」，只把「勾掉」换掉 | 少改一个词 | 否决：需求方点名「抄」难听；「记上」与已保存状态「已记下」同族，整屏语气才统一 |

## 影响

- **得到**：小节标题先被看见、正文退成成段手稿，日期头仍是全屏最大；空表单第一行就是提示与光标，不再像两行错位的小字；动作文案从「抄」变成自己的记账动作，符合「写给自己」的定位（ADR-0032）。
- **付出**：日报正文与待办正文出现 1sp/3sp 的差，跨屏切换能看出来；`UnderlineField` 多一条按行数分支的对齐规则，读书页也要跟着回归；ADR-0032 的字阶与「抄」字结论作废，文档要同步。
- **返工点**：一周后仍嫌大，按备选表把正文退到 15/26，标题与空态不动；若嫌小则回 17/30 并重新看标题。两处都只动日报样式副本，不碰 `Theme.kt`。
- **连带决定**：本条只部分取代 ADR-0032——被取代的是「提示 13/20、小节标题 15/21、正文保持 17/30」这组字阶，以及两个动作叫「抄」的命名；自动保存与补存、日历墨点与当日入口、不写未来的客户端与服务端校验、三段结构与 2000 码点上限全部继续有效。按 writing-rules §3，ADR-0032 正文不改、状态仍为「生效中」，取代范围记在这里。

## 复查条件

- 真机或模拟器用满一周，仍觉得日报正文大或小——按备选表在 15/26 与 17/30 之间二选一，不再逐次微调。
- 跨待办与日报切换时，1sp 的正文差被明确指认为「抖」——做一次全局字阶复查，而不是把日报改回 17/30。
- 读书页的心得框顶对齐后，提示与第一行正文的基线关系看起来不对——给 `UnderlineField` 补一个显式对齐参数，只让需要的屏打开。
- 系统字号 2.0x 下任一段出现裁切或提示被吞——先修布局，不改字阶。

## 替代成本参考

写作类产品的正文通常比清单低半档、行高更松（Day One、Apple Journal 的正文都靠行距而不是字号撑呼吸感）；小节标题普遍是小号半粗无衬线，靠字重和字距而不是尺寸分层。空表单的占位语跟随第一行书写位置，是表单的通行做法，居中只适合单行搜索框。
