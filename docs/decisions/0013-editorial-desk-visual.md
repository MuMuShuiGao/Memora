# ADR-0013：客户端视觉走「编辑部案头」

> 状态：生效中
> 摘要：记录是原稿、报表是付印清样——纸色底墨色字，衬线排正文、无衬线排界面，靠线分层不用卡片阴影，朱红只给状态与主动作
> 日期：2026-11-26 ｜ 关联：[design/android-client.md](../design/android-client.md)

## 决策

客户端视觉整体换成「编辑部案头」：纸色底（`#F3F3ED`）配墨色字（`#1B1C18`，次级 `#5F6257`），系统衬线体排正文（记录、报表），系统无衬线体排界面字（按钮、标签、日期、状态），全 App 只有朱红（`#B23A2D`）一种强调色，圆角统一 2dp，**不用卡片、不用阴影**——分层靠 2dp 墨色通栏线、1dp 发丝线和缩进。唯一的记忆点是报表状态印章（方框、旋转 -3°，状态变化时按一下），其余保持安静；编辑页一条朱红竖线从页眉通到底部当稿纸左边距。全部实现集中在 `Theme.kt` 与 `Components.kt`，Screen 只做组装。

## 背景

第一版界面是能用的默认 Material 外观：动态取色、白底列表、悬浮按钮。装进模拟器后看着和任何 demo 没区别，而这是给一个人每天写东西的 App，界面不该像模板。约束：只动表现层，网络/存储/业务逻辑逐行不动（ADR-0010 的依赖边界不破）；不引新依赖、不打包字体；保留 Material3 元件的点击区域与无障碍语义。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 纸墨双家族 + 结构线（编辑部案头） | 系统衬线体的中文映射因厂商而异，跨设备字形不一致 | **采纳**：一致性的下限是"可读"，上限不值得为此打包字体；"读文章"的语境里各家宋体的差异反而像印刷批次 |
| Material 默认（动态取色 + 白卡片 + FAB） | 零成本 | 否决：这是唯一一次定视觉的机会，默认外观说不出"这是备忘录"；FAB 还会遮住列表尾行 |
| SaaS 卡片墙（内容切块、统一圆角、统一灰阴影） | 层级只剩卡片尺寸和留白 | 否决：记录是连续文本流，切卡片等于制造不存在的模块边界；阴影落在纸色底上显脏 |
| 报纸大排版（全画线、全零圆角、密集多栏） | 手机上多栏撑不起来 | 否决：窄屏硬套报版只会更挤；这套"发丝线 + 全零圆角"本身也是满大街的模板相 |
| 深色 + 霓虹单色强调 | 暗底亮色小字长文阅读吃力 | 否决：这是白天随手记的工具，不是夜间阅读器；可读性不该给氛围让路 |
| 打包中文衬线字体（Noto Serif SC 子集） | APK 增重 10 MB 起，还要维护字形裁剪 | 否决：9.6 MiB 的包里翻一倍只为字体；API 26+ 的系统 serif 已有中文覆盖 |

一个主动核对过的风险：「纸色底 + 衬线 + 暖红」正好是当下生成式设计最常见的组合。这里的纸色来自产品隐喻（原稿 → 清样）而不是背景偏好，朱红取的是印章色不是陶土色，标题也没有堆高对比大衬线——保留，但记在此处以备复查。

## 影响

- **得到**：界面有唯一记忆点（朱红印章），其余安静；不用卡片也能分层（通栏线、发丝线、缩进），滚动时结构不晃。
- **付出**：`FontFamily.Serif` 在个别低端机或魔改系统上可能回退成无衬线，排版气质打折但不影响功能；视觉验收从此多一条"纸感"主观标准，不能只看截图说通没通。
- **返工点**：色板、字阶在 `Theme.kt`，字段/按钮/tab/印章/提示在 `Components.kt`；整体换方向主要改这两个文件，Screen 里的线与缩进调用可留可删，工作量以小时计。
- **连带决定**：状态印章是全 App 唯一非用户触发动效，别处不加过渡、不加骨架屏；空态与错误用一句人话加方点提示，不用插画；正文左对齐占满行宽，不居中。

## 复查条件

出现以下情况时重新评估本决策：

- 需求方在真机用满一周仍觉得"别扭"——方向问题，不是细节，换视觉比修细节便宜
- 目标真机上 `FontFamily.Serif` 的中文映射缺失（正文回退黑体），气质整体垮掉
- 出现第二个人使用（多用户），届时可能需要更"产品化"的外观

## 替代成本参考

同类写作工具的现成做法：iA Writer 用等宽单栏 + 纯白/纯黑两档；Bear 用极简排版 + 字体选择器；Notion 用系统字 + 结构化块。共同点是不把装饰当主角，字体与留白就是产品语言。本决策走同一条路，只把隐喻换成中文语境下的稿纸与清样。
