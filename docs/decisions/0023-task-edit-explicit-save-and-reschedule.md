# ADR-0023：待办编辑改多行、显式确认并可直接改期

> 状态：生效中
> 摘要：待办行内编辑换成可换行输入框，行尾常驻对勾作显式保存；正文下可直接开日期选择器改 `due_on`；只发改动过的字段
> 日期：2026-11-27 ｜ 关联：[ADR-0020](0020-inline-task-edit.md)、[ADR-0021](0021-calendar-dated-tasks.md)、[ADR-0017](0017-drawn-line-icons.md)、[design/android-client.md](../design/android-client.md)

## 决策

点待办正文仍在原行编辑，但输入框改成 1–4 行自适应（`minLines=1`、`maxLines=4`），IME 回车仍是完成键；行尾常驻一枚自绘对勾（`DeskIcon.Check`）作为这次编辑唯一的显式保存入口——正文再长、换行再多，落定键也始终在行尾，不随键盘与滚动跑掉。编辑态正文下方出现「改期 · M月D日 周X」（已过期为朱色），点开 Material `DatePickerDialog` 选日，确认即把新 `due_on` 记入本次草稿；保存时只对真正变了的字段发 `PATCH /v1/tasks/{id}`，`body` 与 `due_on` 可同发也可各自单发。空白正文按放弃处理；返回键先关日期选择器，再放弃编辑；写失败仍走"提示 + 回滚重拉"。已勾掉的待办照旧可改，`done_at` 与报表归属不动。本决策取代 [ADR-0020](0020-inline-task-edit.md)。

## 背景

需求方 2026-11-27 指出：长正文在单行输入框里只能横向滚动，看不见后半句；IME 的完成键在长文本下不显眼、还可能被键盘挡住，不敢确定按下去是否保存。同一天还发现排期只能在日历页新增时指定，已有待办想改期没有入口——删了重录会丢名次和勾选状态。

约束来自既有定论：服务端 `PATCH /v1/tasks/{id}` 本来就逐字段更新（`body`、`due_on`、`done` 各管各的），`due_on` 只认真实存在的 `YYYY-MM-DD` 且不能清空；待办仍是独立成表的一句话对象（ADR-0014），不为它开整屏编辑器（ADR-0020 已否掉）；行内动作是自绘图标而非文字（ADR-0017）；App 此前没有模态弹窗，错误与提醒都走行内 `Notice`。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 多行输入 + 行尾对勾 + 日期选择器（本决策） | 编辑态行高最多四行，列表位置会跳；引入全 App 第一个模态，Material 组件与案头视觉不同源 | **采纳**：显式键与 IME 完成并存，长正文有确定的落定方式；改期不出待办上下文；日期面板自带可访问性与日历布局，自绘成本留到视觉复查再算 |
| 维持单行，只把 IME 动作换成"完成" | 零改动 | 否决：长文本仍横向滚动；完成键是否在视野内取决于输入法与键盘高度，用户找不到键正是本次要修的问题 |
| 行内加一枚"保存"文字按钮 | 落定入口更直白 | 否决：与 ADR-0017 的图标语言冲突，又会把宽度从正文抢走；对勾与勾选框同一套笔画，"这次是保存"不需要再教一遍 |
| 改期跳到日历页完成 | 复用日历选中日的录入 | 否决：多两次页签与选日，待办上下文丢失，改完还得自己找回来；日历页也不承担改字（ADR-0021 已定只加、勾） |
| 改期用手输 `YYYY-MM-DD` | 实现最省事 | 否决：手机键盘输日期易错，客户端还得复制服务端已有的日期校验；两处校验一旦口径不同就会互相打脸 |
| 弹窗里编辑整条待办 | 字段集中 | 否决：正文编辑失去行内上下文（看不到前后名次），正是 ADR-0020 否掉弹窗的理由；只把日期选择做成模态，范围最小 |

## 影响

- **得到**：长正文可见、可改、一键落定；改期在待办行内完成，名次、完成态与报表归属都不动；只发变化字段，改字不会被旧 `due_on` 覆盖，改期也不会重发正文。
- **付出**：日期选择器是全 App 首个模态，`DatePickerDialog` 的 Material 版式与「编辑部案头」不同源，目前只靠颜色参数对齐；编辑态最高四行，进出编辑时列表会上下跳。
- **返工点**：想把日期面板完全画成案头语言，只需替换 `DueDateDialog` 内部；服务端与调用点不用动。
- **连带决定**：ADR-0020 废弃；`MemoApi.updateTaskBody()` 收成 `updateTask(id, body?, dueOn?)`；打开日期面板前必须 `clearFocus(force = true)` 收键盘，否则键盘与对话框抢高度、面板被压扁（实测踩过）；保存键用 `DeskIcon.Check`，不新增图标字体。

## 复查条件

出现以下情况时重新评估本决策：

- 需求方要求把待办改成"无日期"（清空 `due_on`）——服务端当前按 400 拒绝，要先改契约
- 四行仍装不下成为常态，或正文需要保留换行语义（那就触到 ADR-0014 的复查条件）
- 出现第二个客户端并发改同一条待办，字段级"后写覆盖先写"需要重新定口径（同 ADR-0020）

## 替代成本参考

Things、Todoist 的行内编辑同样是多行文本框配键盘外的完成键，日期一律点日历而非手输；它们把模态留给日期/清单这类离散选择，正文编辑始终留在行内。
