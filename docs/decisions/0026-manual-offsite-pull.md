# ADR-0026：盘外副本改为手动拉取，取消 Windows 计划任务

> 状态：生效中
> 摘要：服务器每日快照不变，盘外副本由人双击本机脚本拉取，不再注册计划任务
> 日期：2026-11-27 ｜ 关联：[0025](0025-backup-snapshot-and-offsite-pull.md)、[design/memo-and-report.md §8](../design/memo-and-report.md)、`deploy/pull-backups.ps1`

## 决策

服务器端保持 ADR-0025 定下的每日 `VACUUM INTO` 快照（保留 5 份）；Windows 侧取消每周计划任务，盘外副本改为手动双击本机入口脚本触发 `deploy/pull-backups.ps1`，脚本仍只保留最新 5 份。本机入口脚本与快捷方式不入仓库。

## 背景

ADR-0025 的 Windows 计划任务只在用户登录时运行、失败不重试，且为一个每周一次的动作常驻一条后台任务。部署与手动拉取都已验通后，需求方决定不要后台自动任务，接受"记得才拉"的代价。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| **手动双击拉取（脚本与保留逻辑不变）** | 靠人记得；忘拉期间盘外副本落后 | **采纳** |
| 保留每周计划任务 | 无感，但只在登录时跑、失败不重试 | 否决：需求方明确不要后台自动任务 |
| 放进登录启动项自动拉 | 开机即拉，不用记 | 否决：仍是后台自动行为，与"自己点"的要求相反 |
| 服务端定时推对象存储 | 不依赖本机开关机 | 否决：ADR-0025 已否——云凭据与外部依赖不值得 |

## 影响

- **得到**：没有后台任务，拉取时机完全由人控制。
- **付出**：忘了拉就没有新的盘外副本；这段时间盘坏，丢的数据可能超过一周。ADR-0025 里"没有机制保证真做"的风险由需求方接受。
- **返工点**：想恢复自动，重新注册计划任务即可，脚本参数与保留逻辑都不用改。
- **连带决定**：脚本头部不再给 schtasks 示例；恢复演练照旧（design §8）。

## 复查条件

出现以下情况时重新评估本决策：

- 实际很少拉取，盘外副本长期停在一个月以前
- 出现一次"因为没拉而丢数据"的事故
