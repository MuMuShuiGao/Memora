# ADR-0027：完成心得可跳过，不做逐条强制

> 状态：生效中
> 摘要：勾掉待办后在不挡列表的位置给一句 ≤50 字心得入口，已完成区可补可改，心得随待办进报表素材；否掉逐条强制、只留已完成区入口、生成前批量补与重要标记强制
> 日期：2026-11-27 ｜ 关联：[design/memo-and-report.md](../design/memo-and-report.md)、[design/android-client.md](../design/android-client.md)

## 决策

每条待办带一个可选的「完成心得」，最多 50 个字。勾掉后屏底浮出一条不挡列表的提示：点「写一句」就地输入，点「先不写」或勾选下一条就走；已完成区里随时能补能改，空串表示没写。报表生成时，有心得的待办把心得作为完成后的补充一起喂给模型；没心得的待办照常进报表，但提示词禁止模型给它补结果。取消勾选不删心得。

## 背景

- 需求方想要「完成即反思」，翻回已完成待办时能看到当时留下的心得。
- 待办是长尾的：交周报和买牛奶混在同一张清单里，逐条强制会命中大量没有反思价值的小事。
- 现有 FR-09 要求「勾一下即完成并立刻离开清单」，v0.7 刚按 ADR-0024 做了快速连勾不吞点击，任何阻塞完成的写法都会直接推翻这两条。
- 报表素材目前只有待办标题（design §6），模型只能写「做完了什么」，不知道做完的结果；心得正好补这一层。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 可跳过的一句话心得：完成瞬间给入口，已完成区可补，进报表 | 一部分待办会没有心得；表多一列、PATCH 多一个字段、两处界面 | **采纳** |
| 每条待办必须写 ≤50 字心得 | 完成动作变成小作文，与快速连勾冲突；琐碎待办只能凑数 | 否决：需求方自己也承认「买牛奶没必要反思」；凑数的「完成了」反而污染报表素材 |
| 只在已完成区开入口，完成时不给提示 | 完全不打扰 | 否决：已完成区默认收起，入口等于不存在；完成那一刻才是记忆最新鲜的时候 |
| 生成报表前把缺心得的待办列出来批量补 | 一次补齐，写得更从容 | 否决（暂缓）：定时报表到点就生成，等不到人；没有提醒机制，批量补可能整批错过。字段与接口已为此留好，复查条件触发时再加 |
| 给待办加「重要」标记，只对重要的强制 | 把反思留给值得的事 | 否决：要引入新维度，而优先级已由名次表达，加一层判断与「随手记」的定位冲突 |

## 影响

- **得到**：报表素材多一层「做完之后发生了什么」，生成稿更接近能直接交出去的正文；完成动作仍然是一下。
- **付出**：每次勾完多一条可忽略的提示；心得会随报表素材发给外部模型（与记录同口径，ADR-0005 不变）。
- **返工点**：想改成强制或生成前批量补，动 `TasksScreen` 的完成流程与报表页即可，表结构与接口不用动。
- **连带决定**：空串表示没写、允许清空；取消勾选不清心得；新建待办不带心得；日历屏不弹心得入口（保持「只做加、勾」），要补去待办页。

## 复查条件

出现以下情况时重新评估本决策：

- 心得的实际填入率一个月内低于一成——入口位置或提示文案不对，重估生成前批量补。
- 库里出现大量「完成了」「还行」这类凑数心得——重估这个入口还值不值得保留。
- 需求方要求把心得单独成列表、可检索——重估是否该把它升成一等对象而不是待办的从属字段。

## 替代成本参考

- Things 3 的 Logbook、Todoist 的完成记录、iDoneThis 的每日一问都是「记录但不强制」。
- 强制完成说明多见于工单/审计场景（如工单系统的 resolution note），那里的目的是追责，不是反思。
- 事后复盘（AAR）只对重要事项做，没有对每件小事逐条做的先例。
