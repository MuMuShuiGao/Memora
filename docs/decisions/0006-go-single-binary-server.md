# ADR-0006：服务端用 Go，编译成单二进制用 systemd 起

> 状态：生效中
> 摘要：一门 Go 写后端，静态二进制 + systemd 起在单个业务端口上，不进 Docker，定时走进程内调度
> 日期：2026-11-24 ｜ 关联：[../projectneed.md](../projectneed.md)、[0007-sqlite-over-postgres.md](0007-sqlite-over-postgres.md)

## 决策

后端用 Go 写，编译成一个静态二进制，由 systemd 拉起，监听一个业务端口（端口值不入档，见 [../writing-rules.md](../writing-rules.md) §9；实测本机已有一个端口被别的服务占着，要避开）。传输层与对外暴露方式不在本条决定范围内，见 [0009-public-ip-selfsigned-https-access.md](0009-public-ip-selfsigned-https-access.md)。SQLite 驱动选纯 Go 实现，不引 cgo，以保证二进制可以拷到同架构机器直接跑。报表定时生成走进程内调度，同时把"生成某个周期的报表"暴露成一个命令行子命令，供手动补跑和单独调试。

## 背景

本机实测：Python 3.10 + pip、PostgreSQL 17、Docker 27 都在；**没有 Go，也没有可用的 node/npm**（运行环境里那个 Node 版本不是给用户开发用的工具链）。可用内存 1568MB，磁盘剩 25G。需求方在被给出"零安装的 Python"和"需要现装但部署面更干净的 Go"之后，选了 Go 并表示后续服务端由自己维护。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| **Go 单二进制 + systemd** | 要在这台机器上装一次 Go 工具链；改一次代码要重新编译再传；样板代码比 FastAPI 多四到六成（估算） | **采纳** |
| Python 3.10 + FastAPI | 依赖散在 host 上（venv + requirements + 版本记录），进程内定时要额外引一个第三方库 | 否决：部署面不如单二进制干净。它唯一硬优势是"已经装好了"，而这条对一次性安装成本来说只值两分钟 |
| Node / TypeScript | 这台机器上 node 和 npm 都不存在（实测），要装的东西比 Go 更多 | 否决：语言统一在这个项目里换不到收益——客户端已定为原生 Kotlin，服务端选什么都是第二门语言。只有走 PWA 全栈 TS 才成立，而 PWA 被 [ADR-0008](0008-native-kotlin-client.md) 否掉了 |
| Java / Spring Boot | 3GB 级机器上一个 JVM 常驻 | 否决：为一个五个接口的应用付不起这块常驻开销 |
| Go + Docker 部署 | 多一层镜像构建与容器生命周期 | 否决：整个应用就是一个进程加一个库文件，容器化不解决任何现存问题，却让"看日志、改配置"多一跳 |

## 影响

- **得到**：部署 = 传一个文件；常驻内存约 15MB（估算）；接口形状在编译期对齐；定时不依赖 crontab，也不需要任何外部调度器。
- **付出**：需求方要长期在本机维护一套 Go 工具链；改代码的往返比解释型语言长；纯 Go 的 SQLite 驱动比 cgo 版慢（本项目的量级无感，但要知道选它的原因是不引 cgo，不是因为它快）。
- **返工点**：换成 Python——读写逻辑、表结构定义、调度全要重写，只有 SQL 语句能留。属于换实现不换设计，前提是接口契约已经先写进 `design/`，否则换语言会连带推翻设计文档。
- **连带决定**：库文件路径必须走配置项，不能编译进常量，否则换个存放位置就要重新编译。数据层的结论单独记在 [0007](0007-sqlite-over-postgres.md)。

## 复查条件

出现以下情况时重新评估本决策：

- 需求方不再愿意在本机维护 Go 工具链——此时"零安装"的价值会立刻反超
- 出现必须用 Python 生态的需求（例如服务端本地做 embedding 或向量检索）
- 进程内调度证明不可靠（进程重启导致漏跑且补不回来）——那时该改的是把定时挪进系统 crontab 并复用已有的命令行子命令，**不是换语言**
