# ADR-0019：刷新图标只留报表页

> 状态：生效中
> 摘要：三屏各一枚刷新图标收成一枚——只留报表页；记录与待办页靠"进屏即重拉、写失败自动回滚重拉"，跨设备的新内容切走页签再回来才看得见
> 日期：2026-11-27 ｜ 关联：[ADR-0017](0017-drawn-line-icons.md)、ADR-0004、ADR-0001、[design/android-client.md](../design/android-client.md)

## 决策

记录页与待办页顶部的刷新图标删除，报表页保留。三屏的"重新拉一次"都不靠图标：切页签会重进组合、`LaunchedEffect` 自然重拉（`App.kt` 的 `when (tab)`）；记录页从编辑页返回同样重进组合；待办的写操作失败已经在代码里自动 `reload++` 回滚。报表页之所以例外，是服务端定时归档（ADR-0004）会在用户盯着这一屏的时候把"生成过的周期"列表改掉——那是唯一一处"没动手机、内容却变了"的地方，需要一个不离开此屏的手柄，且验收里"拖完顺序还在"的验法仍可用切页签完成。

ADR-0017 定的只是字形与图标语言，不涉及落点；本决策收窄落点，0017 继续生效。

## 背景

需求方 2026-11-27 问"页面为什么有刷新、刷新的意义是什么"，解释清楚后决定只留报表页那枚。事实基础：客户端不存业务数据（ADR-0001），屏幕上那份只是某次 `GET` 的快照，没有推送也没有轮询；但上一轮把"重拉"这件事绑在了三枚图标上，而其中两次重拉与"切页签/返回编辑页"完全重叠。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 三屏各留一枚（现状） | 每屏多一个图标位 | 否决：记录与待办那两枚只在"不离开这一屏又想看另一台设备刚写的东西"时用得上，与切页签重拉重复；三处重复反而暗示"这页需要手动同步" |
| 三枚全去掉 | 零图标，最干净 | 否决：报表页的周期列表会被服务端定时任务改掉，用户没有别的办法在不离开此屏时看到；验收里"拖完顺序还在"虽可切页签，但报表这条没有等价动作 |
| 改用下拉刷新 | 手势入口，不占图标位 | 否决：material3 的 PullToRefresh 仍是实验 API（ADR-0017 已记这条），且覆盖不了"切页签本身已经重拉"的事实，等于加手势不加能力 |
| 自动轮询 | 无需用户动作 | 否决：为另一台设备偶尔写一条而让每台设备定时打服务器，绕开"没有推送、打开才拉"的定论（ADR-0015），耗电与限速计数都不划算 |
| 只留报表页刷新（本决策） | 记录/待办看新内容要多一步 | **采纳**：唯一"会自己变"的屏保留手柄，其余交给重进组合 |

## 影响

- **得到**：记录页搜索框独占一行、待办录入行只剩一个"+"，两屏顶部回到最轻；刷新不再被理解成"每页必备的同步按钮"。
- **付出**：记录/待办页看到跨设备新内容、或在加载失败后重试，都要切走页签再回来——这一步没有任何提示，用户得自己知道。
- **返工点**：`NotesScreen.kt`（去掉图标与 `reload` 状态）、`TasksScreen.kt`（去掉录入行的刷新调用；`reload` 保留给失败回滚）。想恢复只是把调用加回去，以分钟计。
- **连带决定**：design §边界与异常「刷新」条、§验收里"点刷新之后还是新顺序"的验法改成切页签往返；`DeskIcon.Refresh` 只剩报表页一个调用点。

## 复查条件

- 需求方实际使用中反复靠"切页签"看新记录/待办——那说明还是缺一个显式手柄，可只在记录页补回
- 出现第三种会因服务端自己干活而变化、又没有"切页签即重拉"兜底的屏
- ADR-0017 的图标语言整体返工：刷新只剩一处，跟着一起改

## 替代成本参考

同类个人工具里列表页顶部的刷新很少见（Things 没有，系统备忘录靠下拉）：它们不是不需要重拉，而是把重拉藏进"进入即拉"。本决策取同一分工，把唯一会自己变的报表页留成例外。
