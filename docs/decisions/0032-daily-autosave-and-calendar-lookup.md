# ADR-0032：日报自动保存，日历按天查阅日报

> 状态：生效中
> 摘要：日报改为停顿 1.5 秒自动保存、翻页与跳转前补存，文案换成写给自己的话；日历加日报墨点与当日入口，不新建日历屏；服务端补「不写未来」校验；字阶只做两屏局部调整
> 日期：2026-11-28 ｜ 关联：[0031](0031-handwritten-daily-as-report-material.md)、[0021](0021-calendar-dated-tasks.md)、[0013](0013-editorial-desk-visual.md)、[../projectneed.md](../projectneed.md) FR-18、[../design/android-client.md](../design/android-client.md)、[../design/memo-and-report.md](../design/memo-and-report.md)

## 决策

日报取消底部的「存」：输入停顿 1.5 秒自动 `PUT` 三段全文，翻日期或从日历跳转前先补存，失败保留输入并给「没记下 · 重试」；不再有「未保存不许翻页」。三段标题与提示改成写给自己的话（今天要紧的 / 做成了什么 / 卡在哪儿了），两个「带入」改叫「抄」，日期相对词用「前天」。日历成为按天总览：格子里加一枚 3dp 墨点表示这天有日报，选中日多一行「日报 · 已记下 / 还没写」，点了切到日报屏并落在那天；不新建日报日历或日报列表，也不在日历里编辑日报。为支撑月视图，新增 `GET /v1/dailies?from=&to=`，回有内容的 `entry_day` 与服务端 `today`；`PUT /v1/dailies/{day}` 补上「不晚于服务端 today」的校验。字阶只动日报与日历两屏（提示降到 13/20 无衬线、小节标题 15/21、正文保持 17/30），全局 `Theme.kt` 不动。

## 背景

- 需求方 2026-11-28 反馈：日报能用，但文案像工作汇报、显式保存像提交表单；希望按用户视角放松措辞，并要能按日历查阅日报。
- 现有日报设计第 5、6 条是「显式保存、未保存不许翻日期」。翻页被挡与新增的日历跳转直接冲突：要么跳转也被挡，要么静默丢字。
- 日报屏只有箭头，翻到两周前要连点十几次；日历已有按天网格（ADR-0021），是现成的翻阅入口。
- 服务端目前只校验日期格式，`PUT` 能写未来；设计写的「不写未来」实际只在客户端箭头处生效。新入口会把这个洞暴露出来。
- 约束：客户端不引新依赖（ADR-0010），不做后台服务或离线队列（ADR-0001/0006）；视觉仍是「编辑部案头」（ADR-0013）。

## 备选方案

| 方案 | 主要代价 | 结论 |
| --- | --- | --- |
| 自动保存 + 日历承载日报点与入口 + 区间接口 + 未来校验 | 1.5 秒丢字窗口；日历多一路请求；接口数 +1 | **采纳** |
| 保留显式保存，翻页时给「记下并翻页」 | 不改保存语义 | 否决：日历跳转仍要先落盘，冲突没解决；写完切走仍可能丢最后一段 |
| 新建「日报日历」屏或日报列表屏 | 一个屏、一套月网格 | 否决：抽屉已有六项，第二个日历要同时维护；看旧日报时通常也想看当天待办，分屏把「那天」割成两处 |
| 日报屏内嵌月历 | 写作屏变重 | 否决：与「一分钟一页」冲突，且重复实现 ADR-0021 已有的网格与选中日状态 |
| 日历格内显示日报摘要或正文 | 翻看更直接 | 否决：48dp 格子放不下，且会与任务计数徽标抢位置 |
| 每天一个 GET 拿 42 格 | 不改服务端 | 否决：进一次日历发 42 个请求，失败面与等待都放大；区间接口一次即可 |
| 只靠客户端挡未来日期 | 改动最小 | 否决：新入口把未来写路径暴露给界面；服务端必须兜底 400 |
| 全局字阶 +1 | 一次改完 | 暂缓：牵动十屏的换行与密度；先局部改两屏，真机用一周再评估 |

## 影响

- **得到**：写日报不再有提交感，翻页与跳转不丢已写的字；日历一眼看出哪天写过、点一下就到；未来日期在客户端与服务端都写不进去；空表单的提示不再压过正文。
- **付出**：自动保存通常最多丢最后一两秒（连续输入不停顿或断网时可能更多）；保存失败需要常驻状态与重试；日历的日报点依赖新接口，失败时只能给提示不画点；接口数二十四变二十五、客户端挂起函数二十五变二十六。
- **返工点**：若要做离线草稿队列或后台保存，需要新依赖与调度，按 ADR-0010/0001 重谈；若要日报阅读视图、搜索或导出，是另一个对象，另开设计与 ADR。
- **连带决定**：日历的写操作仍然只有加、勾；日报行只跳转。空三段仍按没有素材处理，日历点也不显示。日报正文仍用 17/30，不靠缩小正文换精致。`PUT` 未来日期回 400 `bad_request`，调用方按服务端 message 提示。

## 复查条件

- 自动保存长期出现「报表取到的是上一版」或失败重试频繁——调整 1.5 秒窗口，或退回更明确的保存提示。
- 日历的日报点与日报行一个月内几乎没人用——重估入口，考虑只在日报屏做月份条。
- 真机用满一周仍觉得字号小——单独做一次全局字阶复查，不在这条里继续加码。

## 替代成本参考

写作类产品默认自动保存：Day One、Apple Journal 都不让用户按「保存」，只给落盘状态；日历类产品把日历当同一批数据的一个视图，不建第二份（ADR-0021 已引 Things、滴答清单）。本条沿用这两点，不引入提醒、打卡或日报列表。
