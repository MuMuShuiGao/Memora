# Memora 需求说明

> 状态：生效中
> 摘要：给一个人用的安卓备忘录，随手记零碎想法，由大模型按自然周/自然月汇总成周报和月报

**项目一句话**：帮我在不用动脑整理的前提下，把一天里随手记下的碎片变成能直接交出去的周报和月报。

---

## 1. 目标

现在写周报要靠回忆这一周干了什么，翻聊天记录、翻待办，常常漏掉做过的小事，一份周报花二十分钟。

做成之后：平时只管往下扔一句话，不用分类、不用打标签；到周五打开 App 点一下（或者根本不用点，报表已经在那了），拿到一份按自然周/自然月归好的正文，复制走就能交。

判断这件事成功与否只有一个标准：**生成的正文我改几句话就能交出去**，而不是还要重写一篇。

## 2. 范围

### 做

- 安卓端随手记一条纯文字想法，增删改查
- 按时间倒序浏览、按关键词过滤已有记录
- 随手记一条待办，勾一下就完成，写错了直接改字；按我自己排的顺序只露最前五条，其余折叠起来
- 拖动前五条改变顺序，这个顺序在另一台设备上也成立
- 给勾掉的待办留一句不超过 50 个字的心得，翻回已完成的待办还能看见
- 按月看每一天安排了哪些待办，直接在某一天下面加一条；日历里加的和待办页里的永远是同一批
- 给跨多周的长待办挂几个阶段，勾掉一个阶段，当周的周报里就能写到这件事推进到了哪一步
- 记下读过的书：书名、作者（可略）、读完的年月，按年翻看
- 给读过的书留一句心得，想写再写，之后还能补改
- 手动生成指定自然周/自然月的报表
- 服务端到点自动生成上一周期的报表
- 查看、复制已生成的报表
- 用一个访问口令挡住非本人

### 不做

| 不做的东西 | 为什么现在不做 |
| --- | --- |
| 图片、语音、文件附件 | 要记的内容一句话就装得下。附件要额外处理存储与上传，而报表环节根本用不上它——喂不进文本模型的信息等于没记 |
| 标签、分组、文件夹 | 条目量级小，靠关键词过滤够找。加了归类就要面对"这条到底属于哪个"的判断成本，与"随手记"相反 |
| 待办的提醒、重复，以及阶段的日期、嵌套与排序 | 日期（安排到哪一天）已由日历引入；阶段只做「汇报点」：一句话、一个勾、可选一句心得，不排日期、不进日历、不占名次。再长出提醒、排期与嵌套，就会把随手记变成任务管理系统。见 [ADR-0021](decisions/0021-calendar-dated-tasks.md)、[ADR-0030](decisions/0030-task-stages-as-report-points.md) |
| 强制每条待办写心得 | 待办是长尾的，"买牛奶"这类没有反思可言；强制只会得到凑数的"完成了"，反而污染报表素材，也拖慢连续勾选。改用可跳过的一句话心得，见 FR-14 |
| 读书的在读状态、评分、封面、豆瓣导入 | 本次只要"读过的书 + 心得"。这些会把随手记录变成图书管理，判断成本与记录成本一起上涨。见 [ADR-0029](decisions/0029-reading-list.md) |
| 读书记录进周报月报 | 周报月报是工作口径，读一本书不等于一份交付，混进去会稀释报表素材。见 [ADR-0029](decisions/0029-reading-list.md) |
| 没做完的待办进报表 | "这周做了什么"只算已经做完的；未完成不代表任何交付。见 [ADR-0014](decisions/0014-todo-tasks-with-priority.md) |
| 敏感信息脱敏（IP、密钥、手机号打码之类） | 需求方明确表示不需要：自用工具，写什么由本人决定，不该由应用替他判断。见 [ADR-0005](decisions/0005-no-redaction-in-app.md) |
| 多用户、注册登录、找回密码 | 只有我一个人用。见 [ADR-0002](decisions/0002-single-user-passphrase.md) |
| 离线记录与联网后补交 | 服务器只在私网可达，断网场景不做支持。见 [ADR-0001](decisions/0001-server-owned-data-on-lan.md) |
| 网页端、快捷指令、微信等其它录入口 | 手机是唯一录入端，多一个入口就多一套需要长期维护的界面 |
| 语音转文字输入 | 安卓系统键盘自带，不在应用里重做一遍 |
| 报表自动发邮箱 / 推到 IM | 查看和复制已经满足交付，自动外发要额外管理收件人和发送失败 |
| 端到端加密 | 内容不含敏感信息，而当前只有口令这一个凭证，达不到端到端的安全模型 |

> "不做"是当前范围的结论，不是永久禁令。出现新需求时，先重估这张表是否还成立，再决定是否推翻——不要拿它直接挡新想法。

## 3. 功能需求

| 编号 | 功能 | 验收线（怎么算做完了） |
| --- | --- | --- |
| FR-01 | 新建一条纯文字记录 | 保存后立刻出现在列表最前面；此时在另一台设备上访问，同一条也能看到（证明副本在服务端而非手机） |
| FR-02 | 修改和删除已有记录 | 改完重开看到的是新内容；删掉的记录不再出现在列表和搜索结果里，也不会进入之后新生成的报表 |
| FR-03 | 浏览与查找 | 列表按记录时间从新到旧排列；输入关键词后能在不打断输入的情况下筛出正文包含该词的记录 |
| FR-04 | 手动生成报表 | 选定"本周/本月/上一个自然周/上一个自然月"后点生成，60 秒内（估算，取决于模型响应）返回正文；生成失败时必须告知失败并允许重试，不允许出现"看起来成功了但是空的" |
| FR-05 | 定时自动生成 | 到达约定时刻后，上一周期的报表无需任何人操作即可在 App 里看到；服务中断导致错过时刻时，恢复后自动补生成，不静默缺失 |
| FR-06 | 查看与复制报表 | 能打开任意周期的报表看到完整正文，一键复制为纯文本；同一份报表重复打开内容一致 |
| FR-07 | 访问口令 | 口令输错时看不到任何记录和报表内容；正确口令只需输入一次，之后打开 App 不用重输 |
| FR-08 | 报表可追溯 | 每份报表正文之外，明确显示它覆盖哪个起止区间、依据了多少条素材 |
| FR-09 | 待办的完成与折叠 | 勾一下即标记完成并立刻离开当前清单，后面的自动补进前五；超过五条时未露出的部分要能展开看到，不需要滚动或翻页 |
| FR-10 | 待办排序 | 拖动前五条中的某一条换位置，松手后顺序就是新顺序并长期保留；在另一台设备上打开看到的是同一个顺序 |
| FR-11 | 待办进报表的口径 | 在本周期内被勾掉的待办出现在报表里，没勾掉的不出现；跨周期勾掉的（上周记的、这周做完）算这一周的 |
| FR-12 | 修改待办正文 | 点正文就地改字，保存后退出重进看到的是新文字；它原来的名次与完成状态不变，已勾掉的改完仍归当初勾掉的那一期报表 |
| FR-13 | 日历与待办同步 | 日历按天显示待办，在某一天下面加一条，切到待办页能看到同一条；待办页新加的落在今天；勾掉或取消勾选后两页看到同一个完成状态 |
| FR-14 | 待办完成心得 | 勾掉一条待办后，不点任何额外按钮就能离开；想写时能在当场留下一句不超过 50 个字的心得，不想写可以直接跳过。之后翻到已完成的这条，能看到并修改这句心得。这条待办进入报表时，心得跟着一起被用上；没写心得的待办照样进报表，但报表不许给它编造结果 |
| FR-15 | 读书记录 | 记下书名（必填）、作者（可略）和读完的年月（默认当月，可改）；保存后立刻出现在对应年份组里、年内按读完月份从新到旧排；此时在另一台设备上打开，同一本书也能看到 |
| FR-16 | 读书心得 | 可以当场写一句不超过 200 个字的心得，也可以先不写、之后在列表里补；改完重开看到的是新内容；把心得清空只清这一句，不删书 |
| FR-17 | 长待办的阶段 | 一条待办可以挂最多 5 个阶段，每个阶段是一句话（不超过 30 个字）；勾掉一个阶段，当周的报表里能看到这件事推进到了哪一步；阶段不排日期、不进日历、不单独占待办名次，也不能再分；不加阶段的待办，界面与现在完全一样；阶段可以取消勾选，进哪一期报表看它自己被勾掉的时刻 |

## 4. 业务口径

| 术语 | 定义 |
| --- | --- |
| 记录 | 一段纯文字，加上服务器保存的创建时间和最后修改时间。一条就是一个想法，不设标题、不设分类、没有完成状态 |
| 待办 | 一段纯文字，外加三样记录没有的东西：我自己排的顺序、有没有勾掉、以及安排在哪一天；它还可以挂最多 5 个阶段。它和记录是两类东西，不互相转换 |
| 安排日期 | 这条待办在日历上属于哪一天，精确到自然日、没有时分。它只决定日历把它放在哪一格，不决定它进哪一期报表——那仍然看完成时刻 |
| 心得 | 一条已完成待办旁边的一句话，最多 50 个字，记的是做完之后的结果或收获。它属于这条待办、不单独存在；取消勾选时心得不删，重新勾上还在 |
| 阶段 | 长待办下面的一个短标题，最多 5 个，勾掉表示这一段做完了。它没有自己的日期、不进日历、不单独占清单名次，也不能再往下分；它把一段较长的工作切成可以分段汇报的节点 |
| 阶段完成 | 勾掉一个阶段的动作。阶段归哪一期报表只看它自己被勾掉的时刻，与整条待办什么时候记下、什么时候勾掉都无关 |
| 读过的书 | 一本已经读完的书，带书名、作者（可空）、读完年月与一句心得。它和记录、待办是三类东西，不互相转换，也不进周报月报 |
| 读完月份 | 一本书读完的那个自然月，精确到年月、没有日。默认是加书时手机的当月，之后可改；按年翻看时只看这个值 |
| 读书心得 | 一本书旁边的一段话，最多 200 个字，记读完的收获或评价。空着就是没写；它不属于报表素材 |
| 当前清单 | 待办里没勾掉的那些，按我的顺序排，前五个是"当前要做的"。前五之外不代表不重要，只代表一屏装不下 |
| 完成时刻 | 勾掉那一下发生的时刻。**待办归哪个周期只看完成时刻**，跟它是什么时候记下的无关——这跟记录的归属口径不同，那条看的是创建时间 |
| 归属周期 | 一条记录属于哪个周/月，只看它的**创建时间**。上周写的记录这周改了几个字，仍然算上周的 |
| 自然周 | 周一 00:00 至周日 23:59，按服务器本地时区（UTC+8，实测）计算 |
| 自然月 | 日历月 1 日 00:00 至月末 23:59，同上时区 |
| 生成中的报表 | 对"本周""本月"这类尚未结束的区间生成时，截止点是生成那一刻，不是周日/月末 23:59。也就是说周中生成的周报只包含到生成当天 |
| 报表 | 一次生成得到的正文产物。生成即成为**快照**：之后这些记录被改动或删除，已生成的报表内容不变 |
| 当前报表 | 一个周期同时只有一份当前报表。对同一周期重新生成会替换掉它，旧的那份不再对外可见 |
| 可用范围 | 手机能直接访问到服务器的那个网络。超出这个范围时本应用整体不可用，这是设计如此而非故障 |
| 访问口令 | 挡住非本人的一串字符，不是账号密码体系，不代表"这个人的账号" |

## 5. 约束

只写产品层面的约束，剥掉实现名后依然成立：

- 记录和待办的副本不能只存在手机上。换手机、卸载重装、手机丢失后，全部历史内容必须能完整找回。
- 生成大模型所需的能力不可用时，已有的记录和已生成的报表仍然可读、可复制——报表功能挂掉不能把备忘录一起带走。
- 还没提交出去的输入不该因为网络突然断掉而整屏丢掉，至少要给用户留一份可复制的原文。
- 记到报表里的是我自己的话，生成的正文不得出现记录和待办里完全没提到过的"事实"（比如编造出一个我没做过的交付物）。
- 换设备使用时不需要在新设备上重新部署任何服务端组件。

## 6. 待确认项

| 问题 | 影响哪部分 | 由谁定 |
| --- | --- | --- |
| 定时生成的具体时刻——周报固定在周一早上还是周五晚上？月报是 1 号还是月末？ | FR-05 | 我（需求提出方） |
| 同一周期重新生成时，要不要保留上一版报表供对比？现在定的是直接替换 | 业务口径「当前报表」、FR-06 | 我 |
| 单条记录长度上限多少？影响一屏能不能看全、以及喂给模型时要不要截断 | FR-01、FR-04 | 我 |
| 报表正文的默认结构是什么（按天流水、按主题归并、还是"本周做了什么/下周计划"）？要不要让我自己挑 | FR-04、FR-08 | 我 |
| 这条内网地址是否长期不变。若网络环境会变，会影响验收时"另一台设备访问"的操作方式 | FR-01 | 我 |
