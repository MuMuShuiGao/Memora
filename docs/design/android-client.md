## 目标与非目标

- 目标：掏出来两次点击内进键盘；所有业务数据只在服务端；把 ADR-0009 那条唯一防线在客户端落实——锁定证书、不留忽略开关、口令密文存放。
- 非目标：不做离线读写（ADR-0001，断网只能继续编辑草稿）；不做通知、小组件、多端、附件；**不算归属周期**（算法只在服务端 `internal/period` 一处）；不做脱敏（ADR-0005）。

## 结构

```
十个 Screen（Compose，主屏六区块 + 连接 / 两个编辑页 / 更新）
      │  只负责显示与输入，不放业务规则
      ├── MemoApi（OkHttp + kotlinx.serialization）── HTTPS ── 服务端 /v1
      ├── UpdateChecker（版本比对 → 下载 → 交给系统安装页）
      ├── CredentialStore（KeyStore 加解密 → 密文进偏好文件）
      └── LocalStore（DataStore：地址、草稿、上次选的周期）
```

| 模块 | 职责 | 依赖谁 |
| --- | --- | --- |
| `AppRoot` 状态机 + 十个 Screen | 显示、输入、把 `ApiError` 翻成文案 | MemoApi、LocalStore、UpdateChecker |
| `MemoApi` | 二十六个挂起函数，请求拼装与错误解析只在这一处 | OkHttp、kotlinx.serialization |
| `ApiError` | 把 HTTP 状态码 + `error.code` 收成界面能分支的十二种情况，`describe()` 给文案 | — |
| `UpdateChecker` | 一次 `check` 决定提不提示，`download` / `install` 只管自己那一步 | MemoApi、偏好文件 `memora.update` |
| `CredentialStore` | 口令的存取，明文只存在于内存 | 系统 KeyStore |
| `LocalStore` | 地址、草稿、报表页上次选的 kind | DataStore |
| Gradle flavor | 默认地址 + 该环境的证书 | 见 §6 |

主屏的六个区块收在左侧抽屉里（ADR-0028），打开 App 仍直接落待办；抽屉只包主屏一层，连接页、编辑页与更新页没有抽屉。区块切换用一个字符串状态，`rememberSaveableStateHolder` 按区块名保住各自的选中日、展开态与草稿。不引导航库：这个 App 只有"连接 → 主屏 → 编辑 / 更新"一条纵深，导航库带来的返回栈、路由参数、目的地序列化都得多写一层，换来的能力用不上。

## 数据

客户端上一共只有五样东西，全都不是业务数据：

| 存什么 | 放哪 | 为什么 | 生命周期 |
| --- | --- | --- | --- |
| 访问口令 | KeyStore 的 AES/GCM 加密后存偏好文件（IV 与密文一起，Base64） | ADR-0008 连带决定：明文落偏好文件等于把 ADR-0002 那唯一防线交出去 | 装到卸载；连接页有"清除口令" |
| 服务器地址 | DataStore 明文 | 地址不是秘密，且换 IP / 换网要能改；值本来就在手机里 | 同上 |
| 未提交的录入正文 | DataStore | 需求 §5 第 3 条：进程被杀不能让用户白打一段字（服务端不管这个） | 保存成功或用户清空后删除 |
| 报表页上次选的周期与 kind | DataStore | 只省点击 | 随时可丢 |
| 更新的两行标记 + 下好的 APK | 偏好文件 `memora.update`、缓存目录 | 前者管"这个版本用户说不再提醒了"和"回来时能说清刚装的是哪版"；APK 是安装器要的文件，不是客户端要的数据 | 标记换版本即失效；APK 系统清理缓存或被覆盖下载时重下 |

**不存记录列表，也不存报表正文缓存**。ADR-0001 定的是服务器为唯一权威副本，而 FR-01 的验收线恰好是"两台设备看到同一条"——手机上留一份缓存，就等于制造第二个真相，而且是最难复现的那种不一致。待办的**顺序同样不落本地**：拖动只改内存里那一份，进程被杀后重进以服务端 `rank` 为准。乐观更新和缓存是两件事，前者活到下一次拉取为止，后者会长期分叉。

## 界面

ADR-0008 说界面三块（列表、录入、报表）。这里有十屏：口令与地址必须有输入入口，那是 ADR-0002 和 0009 的直接后果，不是新增需求；主屏六个区块（待办、日报、日历、记录、读书、报表）排在左侧抽屉里（ADR-0028），打开默认落待办，日报见 ADR-0031，日历见 ADR-0021，读书见 ADR-0029；更新页从主屏报头下方那一行提醒进来，ADR-0015 新增。

| 屏 | 内容 | 什么时候出现 |
| --- | --- | --- |
| 连接 | 地址、口令、"测试并保存"（拿一次 `periods/now` 当验收）、"只保存，先不测"；做成封面页 | 没配过时；之后只在 401 时回来 |
| 待办 | 顶部单行录入（右侧加图标）、前五条（勾选框 + 正文 + 删除图标 + 拖拽把手，点正文进行内编辑）、"展开其余 N 条"、已完成区（已写的心得或「补一句」入口）；非今天的条目在正文下带一行日期；有阶段的任务在正文下多一行「下一步：…」，点开是缩进的阶段清单；勾完屏底浮出可跳过的心得提示条 | 主屏默认区块（抽屉第一项） |
| 日报 | 日期头（‹ 前一天 / 后一天 ›，不越过今天，非今天带「回今天」）、三段多行输入（今天要紧的 / 做成了什么 / 卡在哪儿了）、两个抄入动作（从待办抄五条、抄今天勾掉的）、停顿 1.5 秒自动保存与底部状态 | 抽屉第二项 |
| 日历 | 月网格（周一起始、固定六行，右上角日报墨点）、上/下月与"今天"、选中日的清单（勾选框 + 正文，勾掉的带删除线）与一行日报入口（只跳转）、底部向选中日录入（`due_on` = 选中日） | 抽屉第三项 |
| 记录 | 最新在前、关键词过滤（`q`）、点条目进编辑、底部固定"记一条" | 抽屉第四项 |
| 读书 | 顶部单行录入（书名，回车记下）、总数行、按读完年份分组（年内按月份倒序），每本显示书名、`作者 · M月读完` 与最多四行心得（没心得的显示「补一句心得」） | 抽屉第五项 |
| 编辑 | 多行输入、`n/上限` 计数、保存；已有条目带删除图标（连点两次才删） | 新建与修改共用一屏，整块替换主屏 |
| 改书 | 书名、作者、读完年月（年月选择器，不选日）、心得（≤200 字，近上限才计数）、保存；删除图标连点两次才删 | 点读书页任一本进来，整块替换主屏 |
| 报表 | 周/月切换、周期列表（含 `status`）、单份正文、生成按钮、刷新图标、复制到剪贴板（复制后有确认反馈） | 抽屉第六项 |
| 更新 | 本机版本 → 服务端版本、大小、更新说明、下载按钮与进度、跳过这次、去开系统开关 | 点主屏那行提醒进来，不是区块 |

报头不放"改口令 / 改地址"入口（需求方 2026-11-26 定：连上之后不再主动改）。连接页只在首次启动和 401 时出现；401 时清掉 KeyStore 里的口令与别名再回去。要主动换地址只能重装或清应用数据——地址本来就绑在证书里，换地址要重签证书并重装（ADR-0009）。

三条交互定论，不是建议：

1. **生成按钮点了就转圈到接口返回**。服务端是同步生成（ADR-0004），一次可能要 60s 预算加一次重试；客户端造一个假进度或轮询状态，只会把"服务端正在等模型"这件事藏起来。
2. **进行中的本周/本月也能点生成**（FR-06），界面显示服务端给的 `source_count` 与 `generated_at`，不自己算"截至哪天"。
3. **failed 必须把 `fail_reason` 显示出来**（FR-05 不静默缺失）。`pending`/`running` 在单份响应里出现时显示"进行中"，不许显示成空白正文。

### 待办屏的八条定论

1. **前五在屏、其余折叠，靠展开而不是滚动**（FR-09）。折叠按钮上写清还有几条："展开其余 7 条"。展开是一次本地状态翻转，不发请求——`GET /v1/tasks` 本来就一次给全量（memo-and-report §5.1）。
2. **勾一下就完成，立刻离开前五**，已完成项沉进底部「已完成」区，第 6 名自动顶进前五（ADR-0014）。这是本地先行：先改内存里那份列表，再把 `{done:true}` 发出去；写失败就回滚并显示服务端原文，不能让一次抖动把勾选框卡在错的状态上。
3. **拖拽只在把手上起手势，整列一次提交**（FR-10）。把手吃掉竖直拖动，列表本身的滚动不受影响——两个手势抢同一个方向是这个屏最容易做坏的地方。拖动过程中只改本地顺序（乐观），松手发一次 `POST /v1/tasks/reorder` 带全部未完成 id；失败回滚到拖前顺序并提示，不做半程重试。
4. **前五之外也能拖**：展开之后拖拽作用于整个未完成序列，不是只在前五里换位。"只能调前五"会让第 6 名永远升不上来，那条限制没有任何需求支撑。
5. **录入走屏顶单行框，回车即加**，不进整屏编辑器。待办是一句话（ADR-0014 的边界），为它开一屏违反"两次点击内进键盘"；记录仍然走 `EditorScreen`，两边不共用。
6. **改文字与改期都在行内**（ADR-0023）：点正文，这一行原地换成可换行输入框（预填原文、自动聚焦，1–4 行自适应），行尾常驻对勾作为显式保存键，IME 回车同样保存、返回放弃，空正文按放弃处理。正文下的「改期 · M月D日 周X」点开日期选择器，确认后的日期与正文在同一次保存里只发变化过的字段（`body`、`due_on` 各自可单发）；名次、完成态与勾掉时刻都不动。编辑中这一行收起删除图标与拖拽把手；点另一条的正文先保存当前这条再改那条；切区块等于放弃未保存的修改（页面状态本身跨区块保留，见第 7 条）。
7. **勾选逐行排队，结构写等它清空**（ADR-0024）：每行各自在飞，同一行在飞时再点忽略，别的行可以立刻勾；失败只回滚该行的 `done` 并重拉。新建、删除、拖序等改结构的操作在队列清空后才可用。进屏加载失败显示带「重试」的 `Notice`，不恢复常驻刷新图标（ADR-0019）。五个区块的选中日、展开态与录入草稿跨切换保留；进程重启后不作承诺。
8. **完成心得可跳过，不挡连勾**（ADR-0027）：勾掉成功后屏底浮出一条提示「这条做完了，留一句心得？」——不弹键盘、不改列表、不挡连勾；点「写一句」就地展开输入（≤50 字，按码点计，接近上限才显示计数），点「先不写」或接着勾下一条就把提示换掉（正在写时不抢，草稿不落盘）。已完成区每条在正文下显示心得，衬线小字、左侧一道朱线；没心得的给一个「补一句」，两者点开都是同一条屏底编辑条。取消勾选不清心得；日历屏不弹这个入口，保持「只做加、勾」。

### 待办阶段的七条定论

1. **短待办零变化，入口只在编辑态**（ADR-0030）：没加阶段的任务不显示任何新元素；点正文进入行内编辑时，改期行下方才出现「＋ 加阶段」（已有 5 个阶段时不出现）。点它在该行下方展开阶段区，并追加一条聚焦的阶段名输入；阶段与正文各自保存，谁也覆盖不了谁。
2. **一条待办最多 5 个阶段，按加入顺序排**：没有拖拽、没有日期、不进日历、不占待办名次，阶段下不能再挂阶段。折叠行的文案：还有未勾阶段时写「下一步：<第一个未勾的阶段名>」；阶段全勾完而整条未勾时写「阶段都完了，可以收尾」；整条已勾时写「阶段 N/M」。点这行只展开/收起，不进入正文编辑。
3. **展开区是一段缩进的小注**：每行小勾选框 + 阶段名，行高与待办行一致；点阶段名进入单行编辑（行尾对勾或 IME 完成保存，返回放弃，空名按放弃），编辑态行尾给删除图标，两击确认，与待办同一套。勾掉的阶段留在原位、加删除线，不沉底。
4. **勾阶段复用待办的全套写规矩**（ADR-0024、ADR-0027）：先改本地再发 `PATCH {done}`，同一阶段在飞时再点忽略，失败只回滚该阶段并重拉；勾掉后屏底浮出同一条心得提示（≤50 码点），心得写在展开区的阶段名下方（衬线小字、朱线），没写的给「补一句」。取消勾选不清心得，进哪一期报表看阶段自己的勾掉时刻。
5. **父任务与阶段互不门控**：阶段没勾完也能勾掉整条，阶段全勾完也不会自动勾掉整条；整条勾掉后阶段区保留、可展开查看与补勾补改心得，但不再显示「＋ 加阶段」。
6. **展开状态按 ADR-0024 保留**：按待办 id 记住展开/收起，切区块回来还在；进程重启后不作承诺。阶段名编辑不落草稿，切区块即放弃未保存的输入。
7. **错误显示走同一张表**：加/改/删阶段失败显示服务端 `message` 并回滚该次改动；所属待办已不存在时按其 404 处理，阶段随父任务消失。

### 日报屏的七条定论

1. **抽屉第二项，默认今天，可以向前补记但不能写未来**（ADR-0031、ADR-0032）。日期头写「11月28日 周六」，不是今天时先写相对词（昨天 / 前天 / N 天前），并给「回今天」；右箭头在今天置灰。日期用服务端 `periods/now` 的 `today`，不拿手机日期另算一份——补记要落进哪一周由服务端口径决定，两边时区不同时界面不该先把人带到另一天。日报不依赖模型，key 没填也能写。
2. **只有三段，没有模板系统**：今天要紧的、做成了什么、卡在哪儿了（需求里的优先级 / 完成 / 卡点），各一个多行输入与一句占位提示（「一两件就够」「写结果就行，不用交代过程」「在等什么、什么没做完；没做完的明天接着来」）。提示用 13/20 无衬线，不与 17/30 的正文同权；小节标题 15/21。不设必填、不设心情/工时/打分，也不做模板选择——日报要是一分钟能填完的东西。
3. **两个「抄」动作都只抄文本，抄完即断链**：「从待办抄五条」把当前未完成序列的前五条按行写进优先级；「抄今天勾掉的」把选中日勾掉的待办与阶段按行写进完成段。没有可抄内容时动作不出现，不摆一个点不动的灰按钮。动作不覆盖已经写下的字：空段直接填，非空段只补尚未出现的行。抄进来的是纯文本，之后改待办、拖名次都不回头改日报——日报记的是“那天当时”的快照。
4. **完成段抄入按手机本地日筛 `done_at` / 阶段的 `done_at`**：这是“我那天做成了什么”的展示问题，不是报表归属问题；报表仍按服务端算好的周月归属走，客户端不拿这个筛子去推周期。
5. **自动保存，没有「存」按钮**：输入停顿 1.5 秒发一次 `PUT` 三段全文；保存中又有输入，就等当前请求回来后补一次，两个 `PUT` 不并发。成功只把这次发出的三段作为新基线，状态行显示「已记下 HH:mm」，不回写正在编辑的草稿；失败保留输入、显示「没记下 · 重试」，只有再输入或点重试才再发，不自动无限重试。翻日期或从日历跳转前先补存；若还有在飞的保存，等它回来再换日，失败就留在原页。切区块由 `rememberSaveable` 保住正在写的字；进程被杀通常最多丢最后一两秒（连续输入不停顿时可能更多；已落盘的不会丢）。三段全空只有从有字清到全空才发一次，成功后提示「这天的素材已清掉」。
6. **未来日期不写，服务端也挡**：日期只能到服务端 `today`，日报屏的 `openDay` 与右箭头都以它为准；日历不显示未来日的日报入口；服务端 `PUT` 回 400 兜底。补记旧日期不迁移周期。
7. **404 与三段全空都是空表单，不是错误**：两种都显示三段留空与提示，并在页面上写「这天还没落笔」；其余失败给带「重试」的 `Notice`。打开时不自动发 `PUT`，只有真正输入（或从有字清到全空）才保存——保存成功后不重拉列表。

### 日历屏的七条定论

1. **日历不是第二份数据，是同一批待办按 `due_on` 分天**（ADR-0021、ADR-0032）。它和待办页都读 `GET /v1/tasks` 全量、都在进屏时重拉，所以日历里写的一句切回待办页就在，反过来也一样；日报墨点来自 `dailies` 的 `entry_day`，进屏或换月时按当前 42 格范围一次取回，点开仍是日报屏那一页。客户端不做跨页缓存或自己合并。
2. **格子里一枚计数徽标加一枚日报墨点**：任务数照旧（当天几条就写几，不设上限、不再画短横——朱底纸字，全部勾掉的日子退成灰底；选中日反白成纸底朱字，相邻月再淡一档）。有日报的日子在右上角点一枚 3dp 墨方点，选中日反白、相邻月 40%。日数字用等宽数字，周一格下再带一个 `第N周` 小字（ISO 周），其余格不重复——每格都印周数会把 7×6 的网格变成表格。不写日报摘要，墨点不占徽标位置。
3. **月网格固定六行、周一起始**，相邻月的格子灰显但可点：点它就切到那个月并选它。不做横向滑动手势，那和未来可能加的滚动/拖拽抢方向；上/下月靠两枚自绘箭头，"今天"是一枚文字动作，只在不是本月时出现。
4. **选中日只有一个**：默认今天；切月时选中落到那个月的 1 日；"今天"同时回到本月并选今天。选中日填朱色方块，今天未选中时用朱色数字加 1dp 朱框——两种状态不靠颜色深浅区分。
5. **日历里的写操作仍然只有加、勾；日报行只做跳转**。加走屏底单行录入（预填选中日），勾走与待办页相同的 `PATCH {done}`；改字、拖序、删除仍回待办页，避免把拖拽手势和两次点击的删除确认在月网格里再实现一遍。勾掉的条目留在它那一天，带删除线。选中日表头下多一行「日报 · 已记下 / 还没写」，动作是「翻到这天 / 去写 / 补记」，点了切到日报屏并落在那天；未来的日子不显示这行，日历里不编辑日报。
6. **待办页新增也显式发 `due_on`**（手机当天），不依赖服务端缺省值：服务端时区与手机不一致时，缺省会把一条刚写的待办放到日历的另一天；显式发字面日期则两页看到的永远是同一天。
7. **表头给完成数，勾选与区块状态跟待办页同规**（ADR-0024）：选中日清单的表头写「N 条 · 已完成 M」（有勾掉时才带后半句），勾掉的条目留在当天；勾选逐行排队，失败只回滚那一行。切到别的区块再回来，选中的日子不回到今天。日报日期点单独加载，响应里的 `today` 决定未来日不显示日报行；失败只影响墨点与日报行，给「日报标记没读出来 · 重试」，待办清单照常可用。

### 导航抽屉的四条定论

1. **六个区块收进左侧抽屉，打开仍直接落待办**（ADR-0028）。切区块是"开抽屉 + 点一项"两次点击；返回键先合抽屉，不退出应用。抽屉只在主屏一层，连接页、编辑页、书编辑页与更新页都没有。
2. **抽屉是一页纸色目录**：`ModalNavigationDrawer` 只提供手势与遮罩，样式全自绘——无圆角、无投影、`tonalElevation = 0`；顶部「Memora / 目录」加一道发丝线，条目 48dp，当前项左缘压 2dp 朱线。报头随之改成三横菜单图标 + 「Memora」+ 当前区块名，顶部没有页签以后，位置感从报头右侧补。
3. **区块状态按区块名保留**：`rememberSaveableStateHolder` 以区块名为键，切走再回来，选中日、展开/收起与没发出去的输入草稿都还在（ADR-0024 的状态保留从四个页签扩到六个区块）；进程重启后不作承诺。
4. **编辑与更新仍是整屏替换，不套抽屉**：编辑页、书编辑页、更新页盖住整个主屏，返回直接回原区块，避免未保存的输入被抽屉切走。

### 读书屏的六条定论

1. **加书只要一个书名**：读书页顶部单行输入，回车或加号即记；`finished_month` 显式发手机当月，不让服务端按自己的时区猜（与待办 `due_on` 同规）。作者、月份、心得都点开再补。
2. **列表按年分组，年内按读完月份倒序**：顺序由服务端的 `finished_month DESC, created_at DESC` 决定，客户端只按前四位分组，不重排。组头是衬线年份 + 「N 本」；本地新建后按"不晚于它"的位置插入，不重拉整表。
3. **月份只到月**：书编辑页用自绘的年月选择器（3×4 月份格、年份左右翻、选中月朱底纸字），不借系统日期选择器——那个必须点到"日"，这里没有那一天可选（ADR-0029）。
4. **心得与待办共用同一枚 `TakeawayNote`**：衬线小字、左侧一道朱线；但上限是 200 码点，列表里最多显示四行，编辑页写了 180 字以后才出计数。空串等于没写，清空保存就是清掉。
5. **保存只发变过的字段**：`title` / `author` / `finished_month` / `takeaway` 各自可单发，什么都没改就直接返回。返回键放弃未保存的修改，草稿不落盘——书不是边写边想的东西。
6. **删除两击确认，读书不进报表**：删除与记录/待办同一套确认方式，已在别处删掉的按"已经不在了"回列表；读书页没有任何生成入口，书单也不进周报月报素材（ADR-0029）。

### 更新页的四条定论

1. **提醒只是主屏报头下方一行字，不是弹窗**（ADR-0015）。进主屏查一次 `GET /v1/app/release`，`version_code` 比内置的高才出现；点进去才看到大小、说明和按钮。"打开就弹一屏"违反"两次点击内进键盘"。"这次不提醒"记在 `skipped_version_code` 里，只对那一个版本号闭嘴，发了更新的版本号它自己会重新开口。服务端一个版都没发过（404 `not_released`）时这行字根本不出现，不算错误也不提示"检查失败"。
2. **下载就在 App 进程里跑完，不起前台服务、不挂通知栏进度**。包是 10 MB 量级（估算），一条流写到缓存目录就交出去；服务换来的只是"切到别的应用还能看进度"，代价是常驻通知和一个权限——而那段时间用户其实正在等安装页。
3. **安装那一下不由 App 做**：只把 `FileProvider` 的 content URI 交给 `ACTION_VIEW`，确认框归系统。跳之前先问 `canRequestPackageInstalls()`，没允许就把人送到那个开关前面——Android 8 起按来源逐个授权，硬跳安装页只会得到一句"For your security…"，还回不到我们的界面。开关开完回来点"接着装"，包还在缓存里，不重下。
4. **进度按已下字节 / `Content-Length` 算，1 秒刷一次**；写完之后拿文件实际字节数和清单里的 `size`（服务端 stat 出来的，不是发布时手填）比对，不符就报"下完了但大小不对"，绝不把半包交给安装页——那只会换来一句看不出所以然的解析失败。

## 视觉

方向「编辑部案头」定于 [ADR-0013](../decisions/0013-editorial-desk-visual.md)：记录是原稿，报表是付印清样。实现集中在 `Theme.kt`（色板、字阶）与 `Components.kt`（共用元件），Screen 只做组装。

| 元素 | 取值 | 用途 |
| --- | --- | --- |
| 纸色 | `#F3F3ED` | 全局背景，铺满状态栏与导航栏 |
| 墨色 / 次级墨 | `#1B1C18` / `#5F6257` | 标题、正文 / 日期、说明、占位 |
| 分隔线 | `#CACBBF` | 1dp 发丝线：条目之间、段落之间 |
| 朱红 | `#B23A2D` | 唯一强调色：状态印章、选中下划线、光标、主动作、页边线 |
| 正文 / 界面字 | 系统衬线 / 系统无衬线 | 记录与报表正文、大标题 / 按钮、标签、日期、状态；数字统一 tnum |
| 圆角 | 2dp | 所有元件；不用卡片，不用阴影 |

- **分层靠线，不靠盒子**：2dp 墨色通栏线分大区块（报头、页眉），1dp 发丝线分条目；列表不是卡片堆。
- **状态印章**：报表的 ready/failed 显示为朱红方框、其余墨色，旋转 -3°；状态文本变化时做一次轻微下按——全 App 唯一的非用户触发动效，别处不加过渡、不加骨架屏。
- **页边线**：编辑页一条 1dp 朱红竖线从页眉通到底部，正文从线右侧起排，模拟稿纸左边距。
- **系统栏**：edge-to-edge，系统栏透明、图标深色；`adjustResize` 避让键盘，底栏动作始终在键盘之上。
- **勾选框是 18dp 方框，不用 Material 的 Checkbox**：2dp 墨色直角边、纸色底，勾上之后方框转朱、内部填一枚朱色对勾、正文换 `InkSoft` 并加删除线。它和 `StatusStamp` 同一套语言——形状是方、角是 2dp、强调只有朱红。点按热区是 32dp 的透明方框，画出来的仍是 18dp——触控面积与视觉尺寸分开，行首不额外留白。
- **拖拽把手是右侧三条短横**（`InkSoft`，非强调色）：待办的默认排序语义已经由前五/已完成表达清楚，不需要再显式标"1、2、3"。被拖的那行整体下移跟手、其余行不补动画，松手才落位——ADR-0013 说过别处不加过渡。
- **阶段是一段缩进的小注**（ADR-0030）：展开区左侧压一道 1dp 发丝线、阶段行比待办行缩进 24dp，勾选框沿用 18dp 方框与 32dp 热区；折叠行「下一步：…」是次级墨小字，不带图标；勾掉的阶段加删除线并退成次级墨，不换位置。
- **行内短动词是图标，不是文字**（ADR-0017）：加＝十字、刷新＝留 60° 缺口的圆弧压一枚三角头、删＝描边垃圾桶，全部自绘在 40dp 方形点击区里，字形 20dp、笔画约 1.8dp，跟输入线和发丝线同一套笔画；不用 material-icons 的实心字形。名称只在 `contentDescription` 里。静止态用墨色（删除用次级墨），禁用态次级墨 45% 不透明度，不加旋转或骨架动效——ADR-0013 说动效只归用户触发的那两处。
- **文案**：按钮动词与结果同名（"存"→已保存、"复制全文"→已复制）；错误说清发生了什么，不道歉、不卖萌。
- **更新复用现成版式**：主屏那行提醒是 `Notice`（与限速、错误同一种元件），更新页的进度条自绘成 2dp 方角墨色条而不用 Material 的 `LinearProgressIndicator`——圆角胶囊条放进这套纸色发丝线版面里，看着像另一个 App 塞进来一页。
- **启动图标是同一套语言的对外那一面**（[ADR-0018](../decisions/0018-launcher-icon-ink-mark.md)）：墨底 `#1B1C18` 上一枚纸色描边 M，最后一笔收进转 -3° 的朱色方印；自适应图标只有 anydpi-v26 那份矢量加一张单色层，没有各密度位图。
- **月历是一张账页**（ADR-0021、ADR-0032）：只画每周之间的发丝线，不画竖线也不做圆角格子；日数字用无衬线等宽数字（13sp 不动），每格一枚计数徽标（当天几条写几，不设上限；全部勾掉退灰，选中日反白成纸底朱字）加右上角一枚 3dp 日报墨方点；选中日是填朱的方块、今天是朱色数字加细框。格高 `heightIn(min = 48.dp)`，系统字号放大时向下长而不裁切；周数 9sp，选中日下的日报行 13/18。月份标题用衬线字，上/下月是自绘箭头，和输入线、垃圾桶同一套笔画（ADR-0017）。
- **抽屉是一页目录**（ADR-0028）：纸色铺底、无圆角无投影，条目是一行墨字，当前项只靠左缘一道 2dp 朱线与颜色深浅区分；不出现 Material 默认的药丸底或卡片。报头左侧的菜单图标是三条横线，与拖拽把手、输入线同一套笔画。
- **读书单是一份书账**（ADR-0029）：年份用衬线大标题，右侧「N 本」；每本书名一行，作者与「M月读完」是次级墨小字；心得沿用 `TakeawayNote` 的朱线与衬线小字，列表最多四行，没心得的给「补一句心得」。年月选择器是纸底墨框、3×4 月份格，选中月朱底纸字，不出现日历网格。
- **日报是一页交接班记录**（ADR-0031、ADR-0032）：日期头用衬线大字（21/30），前一天/后一天是自绘箭头；三段各是一条 15/21 无衬线小节标题加一句 13/20 的次级墨提示，下面是 17/30 衬线正文，段间用发丝线隔开，不做卡片也不加底色。两个「抄」是朱色小字动作，放在小节标题右侧；没有「存」键，底部只在保存中、刚保存与失败时出现一行 12/17 状态，失败用朱色 13/18 并可重试。整页只有纸、墨、朱三色，和待办页同一套语言。

## 接口调用与错误显示

请求形状、字段、状态码以 [memo-and-report.md §5](memo-and-report.md) 为准，这里只定客户端拿到每种错误时干什么：

| 情况 | 界面动作 |
| --- | --- |
| `401 unauthorized` | 提示"口令不对"，跳连接页，丢掉内存里的口令。不自动重试——重试只会喂限速计数 |
| `429 rate_limited` | 提示"试太快，N 秒后再试"，N 取 `Retry-After`，期间按钮禁用 |
| `400 bad_request` | 直接显示服务端 `message`（本来就写成人话，如"before 要 RFC3339"） |
| `404 not_found` | "这条已经不在了"，从列表移除该条；日报的 404 是「这天没写」，按空表单处理，不算错误 |
| `404 not_generated` | 空态 + 生成按钮，不算错误 |
| `404 not_released` | 更新通道：一个版都没发过，主屏那行提醒不出现。静默，不许显示成"检查更新失败" |
| `500 release_bad` | 更新通道：清单在而包不在（发了一半），说"服务端只发布了清单"——这条得区别于连不上 |
| `409 no_records` | "这个周期一条记录都没有"，显示成空态而不是错误 |
| `413 too_large` | 正常路径不该出现（客户端先挡），真收到就把服务端原文显示出来 |
| `502 generation_failed` | 显示响应里那条 `report.fail_reason` |
| `503 llm_not_configured` | "服务端没配模型"——这句话要区别于"模型出错"，否则用户会去查自己网不好 |
| `5xx` / `internal` | "服务端出错了"，附 `code` |
| `IOException`（连不上、超时） | "连不上服务器"，附当前地址；这是唯一该提示检查网络的分支 |
| `SSLHandshakeException` / `SSLPeerUnverifiedException` | "证书与地址不匹配，或打进来的证书不是这个环境的"——见 §6，这条几乎总是 flavor 与证书配错了 |
| `GET /v1/dailies` 失败（5xx / IOException） | 日历的待办清单照常；不画日报墨点、不显示选中日日报行，给一行「日报标记没读出来 · 重试」 |

超时：连接 15s，读取 90s。读取必须**大于**服务端单次生成的 60s 预算加一次重试余量，否则客户端先断开、用户看到"连不上"，而报表其实正在库里落地——那是最容易被误判成产品坏了的组合。下载 APK 走同一个客户端：OkHttp 的读取超时算的是**两次读之间**的间隔，不是整包耗时，所以 10 MB 慢慢下也不会被这条 90s 掐断。

## 结构细节：周期从哪来

报表接口要 `period_start`，客户端手上没有这个值，而"算周一"这件事**不许在 Kotlin 里再写一遍**：那条规则一旦有两份实现，改口径就要改两处，而客户端那份没有任何测试能发现它跟服务端不一致，`make smoke` 也测不到它。

所以 `GET /v1/periods/now`（见 memo-and-report §5）返回当前周与月的起止日，报表页启动时取一次，"生成本周"直接拿 `week_start` 调生成。客户端拿到什么就用什么，绝不解释、绝不推算。日报页的「今天」与右箭头边界同样取这个响应的 `today`，不拿手机日期另算一份；日历选中日的日报行用日报区间响应里的 `today` 判断，格子的「今天」仍按手机日期（ADR-0021），两者不同时以服务端的日报边界为准。报表、日报与日历的日报行共用同一口径；格子的「今天」是唯一的例外。

## 6. 构建环境与证书

两个 flavor（`local`、`server`），同一份源码，差的只有两样东西：

| | `local` | `server` |
| --- | --- | --- |
| 默认地址 | 模拟器访问宿主机的固定别名地址（`10.0.2.2` 那个），配 Windows 上跑的 `memora.exe` | 空串，必须在连接页手填——公网地址因此既不进仓库也不进 APK |
| 打进包的证书 | 只覆盖模拟器别名与回环地址那张，**进仓库**：值本身不含任何机器标识，换来"clone 完就能编译"，对应私钥不在仓库里 | 服务器上那张（SAN 是实际地址），只被拷进 `res/raw/`，永不进仓库 |
| 产物 | `app-local-debug.apk`，只进模拟器 | `app-server-release.apk`，装手机并当作发版的那个包 |

签名不属于 flavor 差异，四个变体（`local`/`server` × `debug`/`release`）共用仓库外的同一把 `~/.android/memora.keystore`（别名 `memora`，口令写在用户级 `~/.gradle/gradle.properties`，都不进仓库）：覆盖安装的前提是签名一致，用 AGP 默认的 debug key 签其中一个，以后换构建类型就得先卸载一次——等于把 ADR-0015 那条更新通道废掉一半。keystore 不在时构建照走 AGP 默认签名，为的是别人 clone 完还能编译。

模拟器不必非得连本机服务端：它和真机一样能出网，`serverDebug` 填云机地址就是同一条链路，差别只在打进包的那张证书（构建步骤见仓库 `android/README.md`）。

锁定方式是**把服务端那张证书作为唯一信任锚**（`network_security_config.xml` 里 `trust-anchors` 只引用 `@raw/memora_server_cert`，不设 `debug-overrides`，代码里也没有忽略证书的开关）。选它而不是 SPKI 摘要锁定，理由很实际：漏拷证书文件时资源不存在 → **编译失败**；而摘要写法漏了照样能编译，只会在运行时永远握手失败，报错还不说人话。把错误从运行期推到编译期，是这套 flavor 设计里最值钱的一条。

配套要求：签证书时用 `MEMORA_PUBLIC_IP=<地址1,地址2>` 传多个地址（`deploy/mkcert.sh` 支持逗号分隔，不带前缀按 IP 处理）。证书换了一定要重装 APK——这是 ADR-0009 明写的付出，客户端侧不做任何绕过。

## 边界与异常

- **正文为空或全空白**：不发请求，保存按钮置灰（服务端回 400，但没必要跑一趟）。
- **长度上限**：客户端按 2000 先挡并计数，**数的是码点数**——服务端那份是 `utf8.RuneCountInString`，按 UTF-16 长度算的话带表情符号的记录会被客户端提前挡下。真超限服务端回 413 不静默截断。两处都有这个数字是有意的取舍，见未决问题。
- **进程被杀**：输入变化后去抖 400ms 写草稿，重进编辑页先回填草稿；回填没完成前输入框不留给用户打字，否则那几个字会被后到的草稿盖掉。
- **删除**：连点两次才发请求（这个图标和"取消"挨着，误触代价是丢一条只有手机上记得的想法）。第一次点只给垃圾桶盖一枚 1.5dp 朱色方框、字形转朱，不换文字——文字版那条"确认删"会把整行的正文与拖拽把手左右挤歪（ADR-0017）。确认不是常驻态：第一次点完只要点了别处——输入区、勾选、别的行、空白处、切区块，或者按了返回——朱框立刻撤掉，不发任何请求；换点另一只垃圾桶则把确认挪过去（同时只有一条待确认）。待办行与编辑页两处同一套。成功回 204；已删除再删回 404，界面按"已经不在了"处理，不报错。
- **改待办正文与改期**（ADR-0023）：点正文进行内编辑，输入框 1–4 行，行尾对勾或 IME 完成保存，返回放弃；空白按放弃处理，不删条、不发请求。正文下的改期行点开日期选择器，确认后的日期与正文在同一次保存里只发变化过的字段，只改日期也允许。写失败照待办写操作的规矩提示并回滚重拉。已勾掉的也能改，`done_at` 与归属列不动；不做草稿，切区块或进程被杀后未保存的修改不保留。
- **勾选并发**（ADR-0024）：同一行在飞时再点忽略，别的行不受影响；失败只回滚该行 `done` 并重拉。新建、删除、拖序在勾选队列清空后才可用。五个区块的选中日、展开/收起、录入草稿跨切换与编辑页往返保留；进程重启后不作承诺。
- **完成心得**（ADR-0027）：≤50 个码点，客户端按码点截住输入，服务端超限回 400 并显示原文；空串等于没写，保存空就是清掉。写失败照待办写操作的规矩提示并回滚重拉；不写不发请求。心得只在待办页显示，日历不显示也不编辑；切区块或进程被杀后没保存的草稿不保留。
- **待办阶段**（ADR-0030）：一条最多 5 个（满后「＋ 加阶段」消失，服务端同样回 400 兜底）；阶段名空白不发请求，按码点截住 30；阶段心得按码点截住 50，空串等于清掉。勾阶段失败只回滚该阶段并重拉；加/改/删阶段失败显示服务端原文。已勾掉的待办仍可展开阶段、补勾与补改心得，但不再加新阶段；阶段名编辑不落草稿。
- **日历上的日期**：`due_on` 一律由手机按选中日发 `YYYY-MM-DD`，不做时区换算；服务端只校验是不是合法的自然日。日历里加条目失败照待办写操作的规矩提示并回滚重拉；切换月份是纯本地状态，不发请求。
- **主屏导航**（ADR-0028）：抽屉开着时返回键先合抽屉；抽屉只在主屏，编辑页、书编辑页、更新页和连接页没有。切区块会把当前屏拆掉再用 `rememberSaveableStateHolder` 恢复，没进 `rememberSaveable` 的瞬时状态（如正在飞的通知）不保证跨区块存活；进程重启后区块落回待办。
- **读书单**（ADR-0029）：书名空白不发请求；书名/作者/心得按码点截住输入（100/100/200），月份只能是 `YYYY-MM`；保存只发变化过的字段，四项都没改直接返回；`404` 按"已经不在了"回列表，不报错；返回键放弃未保存的修改，草稿不落盘。加书与改书失败显示服务端原文，列表加载失败给带「重试」的 `Notice`。
- **日报**（ADR-0031、ADR-0032）：三段各按码点截住 2000，全空白按没有处理，清空即清掉这天的素材；输入停顿 1.5 秒自动保存，翻日期或从日历跳转前先补存，失败保留输入并给「没记下 · 重试」，不再有「存」按钮与未保存挡翻页；日期只能是合法自然日且不晚于服务端 `today`，客户端与服务端都挡，`400` 显示服务端原文；`404` 与三段全空都是空表单，给「这天还没落笔」，其余加载失败给带「重试」的 `Notice`。抄入只补尚未出现的行，不覆盖已写文字，抄完不再与待办联动。
- **日历的日报标记**（ADR-0032）：进屏或换月时按当前 42 格范围拉一次日报日期，失败只影响墨点与日报行，待办清单照常；点日报行切到日报屏并落在那天，不在这里编辑日报。
- **时间显示**：服务端给的是 UTC 时间戳，界面按手机时区格式化。**周期一律用服务端返回的 `week_start`/`month_start`**，不用手机日历推。
- **并发**：同一时刻只允许一个生成请求在飞（按钮禁用），服务端另有周期级互斥。
- **列表分页**：`limit=200`（服务端上限）加 `before` 游标翻页，不做本地缓存；上一页没满 200 条就收起"更早的"，到底了还亮着按钮，用户会当成网络问题。
- **刷新只剩报表页一枚图标**（[ADR-0019](../decisions/0019-refresh-only-on-reports.md)）：记录页与待办页的"重新拉一次"发生在进屏时——切区块会重进组合、`LaunchedEffect` 自然重拉，从编辑页返回同理，写操作失败则自动回滚重拉；报表页保留图标，是因为服务端定时归档会在用户盯着这一屏时改掉周期列表。代价摆明：另一台设备刚记的那条，在记录/待办页要切走区块再回来才看得见，且没有提示；加载失败时给带「重试」的行内 `Notice`（ADR-0024）。没有下拉刷新（material3 里还是实验 API），也没有推送。
- **更新下载中途断掉**：写 `app.apk.part`，写完才改名，所以半包永远不可能被交给安装页；重进更新页从 0 重下而不是续传——服务端支持 Range，但客户端要接续就得另存偏移并校验，10 MB 量级下这笔状态机不值得写（估算）。

## 验收

分两级，各自验到什么要写清，别混着报：

1. **模拟器级**（`local` flavor + Windows 上 `memora.exe`）：记录增删改查、搜索、超限行文、口令错误与限速、报表生成与复制、failed 显示原因；待办加/勾/改/展开/拖拽五件事——改是点正文改一处字、行尾对勾落定；长正文换行后仍能看见落定键，正文下的改期行把日期改到另一天且只发 `due_on`；切区块回来是新文字且名次与勾选状态不变；快速勾不同两行都生效；加载失败点「重试」恢复；拖完之后切走区块再回来顺序仍在新位（证明 rank 落在服务端而非内存）；心得那一轮——勾完一条屏底出现提示，写一句保存后已完成区显示、切走区块再回来还在；「先不写」直接消失且不发请求；已完成区「补一句」能再补、清空后保存能清掉；日历三件事——选中另一天加一条，切回待办页能看到同一条且带那天的日期；在待办页加一条，日历的今天格与清单里出现它；在日历里勾掉某条，待办页的已完成区同步；上/下月与"今天"各点一次；抽屉与读书——六个区块逐一切换、返回键先合抽屉而不是退出、编辑页与更新页没有抽屉；读书页加一本默认落在手机当月，补作者与心得后列表显示，年月选择器翻年选月，跨 2025/2026 分组且年内顺序不乱，两击删除后空态回来；阶段那一轮——给一条待办加两个阶段，折叠行出现「下一步：…」，勾一个换到下一个、全勾完变收尾文案，展开收起切区块再回来仍保留，勾阶段屏底出心得提示、写一句后展开可见，改阶段名与两击删除都生效，短待办屏不出现任何新元素；日报那一轮——默认今天，写三段等 1.5 秒看「已记下」，立刻点 ‹ 不丢字并翻到昨天空表单，再翻回今天文字还在，「回今天」从昨天也能一键回来；「从待办抄五条」出现前五条、「抄今天勾掉的」出现当天勾掉的事项，手删一行再抄只补回缺的那行；明天箭头置灰，未来日报入口不出现；三段全清后日历格上的墨点消失；日历选中日出现日报行，点「翻到这天」落在当天；系统字号 1.3x/2.0x 下两屏不裁切；生成周报时 `source_count` 把日报算进去；更新链路四步——提醒行、更新页、下载进度、系统安装页被真正拉起。这一级出不了门——它不碰公网，也证明不了手机能连上服务器。
2. **手机级**（`server flavor` + 服务器）：FR-01"两台设备看到同一条"（含书单）、蜂窝网可达（要安全组入站规则已加）、真 DeepSeek 返回的报表质量、首次更新那一页"允许安装未知应用"的引导在真机厂商 ROM 上是否还成立。

工程可编译可运行（Windows 实测）：`./gradlew :app:assembleLocalDebug` 出 APK，模拟器经 `10.0.2.2` 连上本机 `memora.exe`，记录增删改查、搜索、超限、报表生成与复制都点过。待办四件事在同一条链上点过：屏顶录入 → `POST /v1/tasks` 201 落队首；勾一条 → 它沉进已完成区、第 6 名顶进前五、`PATCH` 200；"下面还有 N 条"展开与收起；拖把手把第 1 条拖下去 → `POST /v1/tasks/reorder` 200，**切走区块再切回来还是新顺序**（重进即重拉，名次确实落在服务端）。报表这一轮仍用假模型，界面上"用了 3 条素材" = 2 条记录 + 1 条本周勾掉的待办，FR-11 在客户端这一侧也对上了。

抽屉与读书屏也在同一台模拟器上点过：五个区块逐一切换、返回键先合抽屉、报头区块名跟着变；读书页加一本 → `POST /v1/books` 201，默认月份是手机当月，列表按年份分组，补作者与 200 字内心得 → `PATCH` 200 且返回后仍在原位，年月选择器翻到上一年选月 → 分组跟着换年，两击删除 → `DELETE` 204 后回到空态。测试书已删净，`GET /v1/books` 回到 `{"books":[],"count":0}`。**没验的**：书单在另一台真机上的同步，以及带书的一次真实生成——后者按设计不该出现书（§6 只取记录、待办、阶段与日报）。

更新链路在模拟器上过了一遍：本机 `memora.exe` 配 `MEMORA_RELEASE_DIR`，拷进 `release.json`（`version_code=99`）与那份 APK，进主屏出"有新版 v0.9 测试（9.7 MB）可更新"，点进去显示"本机 v0.2 → v0.9 测试，约 9.7 MB"与说明，下载走到 44% 时进度行实时刷，写完 logcat 里能看到 `ACTION_VIEW` 把 `content://…fileprovider/…` 交给了 `com.google.android.packageinstaller`，校验结果 Pass。收口那一步用 `adb install -r` 覆盖旧包验的（签名一致才装得上，这正是那把共用 keystore 换来的）。**没验的**：`versionCode` 自己涨 1 之后回到 App 的"刚装好"那一屏；以及公网上的真实发版（服务器目录至今没放包，故意的——放了那行提醒就会开始唠叨需求方的手机）。`serverDebug`/`serverRelease` 要能编译，前提是需求方把服务器那张证书拷进 `res/raw/`——仓库里没有它，fresh clone 上这一步按设计就该失败，那本身就是 ADR-0009 那条防线的验证。

## 未决问题

| 问题 | 卡住哪部分 | 计划怎么定 |
| --- | --- | --- |
| 上限 2000 在客户端是常量 | 只影响输入框计数与提示时机 | 先用常量 + 服务端 413 兜底；真要变成可配再开一个只读配置接口，不在 `periods/now` 里塞 |
| 自动保存去抖 1.5 秒是常量 | 只影响落盘时机与丢字窗口 | 先用常量；出现「报表取到上一版」或失败频繁再调 |
| 阶段数量 5、阶段名 30 码点是常量 | 只影响入口出现与输入截断 | 先用常量 + 服务端 400 兜底；要可配再议，与 2000 那条同规 |
| 检查更新的时机 | 只在进主屏时查一次，长期挂着不提醒 | 先按"打开才查"用；真出现"几周不打开"再考虑 `WorkManager`，那要多一个依赖（ADR-0010） |
| 改口令后的客户端体验 | 改了服务端哈希，旧口令立刻 401 | ADR-0009 已定行为，界面靠 401 跳连接页重输，不做额外入口 |
| 应用名 | 纯外观 | 图标已按 [ADR-0018](../decisions/0018-launcher-icon-ink-mark.md) 定死；名字仍是 `strings.xml` 里的 `Memora`，要不要换个中文显示名归需求方 |
| 生物识别解锁 | 现在只有 Keystore 加密的口令 | 需要时按 ADR-0010 的复查条件重谈 |
