# 安卓客户端设计

> 状态：生效中
> 摘要：手机端界面划分、本地只存哪五样、十五个接口怎么调、每种错误显示成什么、地址与证书怎么随构建环境切换

> 更新：2026-11-27（行内短动词改图标按 ADR-0017；启动图标按 ADR-0018；刷新只留报表页按 ADR-0019）

## 目标与非目标

- 目标：掏出来两次点击内进键盘；所有业务数据只在服务端；把 ADR-0009 那条唯一防线在客户端落实——锁定证书、不留忽略开关、口令密文存放。
- 非目标：不做离线读写（ADR-0001，断网只能继续编辑草稿）；不做通知、小组件、多端、附件；**不算归属周期**（算法只在服务端 `internal/period` 一处）；不做脱敏（ADR-0005）。

## 结构

```
六个 Screen（Compose）
      │  只负责显示与输入，不放业务规则
      ├── MemoApi（OkHttp + kotlinx.serialization）── HTTPS ── 服务端 /v1
      ├── UpdateChecker（版本比对 → 下载 → 交给系统安装页）
      ├── CredentialStore（KeyStore 加解密 → 密文进偏好文件）
      └── LocalStore（DataStore：地址、草稿、上次选的周期）
```

| 模块 | 职责 | 依赖谁 |
| --- | --- | --- |
| `AppRoot` 状态机 + 六个 Screen | 显示、输入、把 `ApiError` 翻成文案 | MemoApi、LocalStore、UpdateChecker |
| `MemoApi` | 十六个挂起函数，请求拼装与错误解析只在这一处 | OkHttp、kotlinx.serialization |
| `ApiError` | 把 HTTP 状态码 + `error.code` 收成界面能分支的十二种情况，`describe()` 给文案 | — |
| `UpdateChecker` | 一次 `check` 决定提不提示，`download` / `install` 只管自己那一步 | MemoApi、偏好文件 `memora.update` |
| `CredentialStore` | 口令的存取，明文只存在于内存 | 系统 KeyStore |
| `LocalStore` | 地址、草稿、报表页上次选的 kind | DataStore |
| Gradle flavor | 默认地址 + 该环境的证书 | 见 §6 |

页面切换用状态机（`AppRoot` 决定显示哪一屏，编辑页和更新页都是把主屏整块换掉），不引导航库：这个 App 只有"连接 → 主屏 → 编辑 / 更新"一条纵深，导航库带来的返回栈、路由参数、目的地序列化都得多写一层，换来的能力用不上。

## 数据

客户端上一共只有五样东西，全都不是业务数据：

| 存什么 | 放哪 | 为什么 | 生命周期 |
| --- | --- | --- | --- |
| 访问口令 | KeyStore 的 AES/GCM 加密后存偏好文件（IV 与密文一起，Base64） | ADR-0008 连带决定：明文落偏好文件等于把 ADR-0002 那唯一防线交出去 | 装到卸载；连接页有"清除口令" |
| 服务器地址 | DataStore 明文 | 地址不是秘密，且换 IP / 换网要能改；值本来就在手机里 | 同上 |
| 未提交的录入正文 | DataStore | 需求 §5 第 3 条：进程被杀不能让用户白打一段字（服务端不管这个） | 保存成功或用户清空后删除 |
| 报表页上次选的周期与 kind | DataStore | 只省点击 | 随时可丢 |
| 更新的两行标记 + 下好的 APK | 偏好文件 `memora.update`、缓存目录 | 前者管"这个版本用户说不再提醒了"和"回来时能说清刚装的是哪版"；APK 是安装器要的文件，不是客户端要的数据 | 标记换版本即失效；APK 系统清理缓存或被覆盖下载时重下 |

**不存记录列表，也不存报表正文缓存**。ADR-0001 定的是服务器为唯一权威副本，而 FR-01 的验收线恰好是"两台设备看到同一条"——手机上留一份缓存，就等于制造第二个真相，而且是最难复现的那种不一致。待办的**顺序同样不落本地**：拖动只改内存里那一份，进程被杀后重进以服务端 `rank` 为准。乐观更新和缓存是两件事，前者活到下一次拉取为止，后者会长期分叉。

## 界面

ADR-0008 说界面三块（列表、录入、报表）。这里有六屏：口令与地址必须有输入入口，那是 ADR-0002 和 0009 的直接后果，不是新增需求；待办是主屏的第一个页签（打开默认落在这里），记录、报表依次其后，ADR-0014 新增；更新页从主屏报头下方那一行提醒进来，ADR-0015 新增。

| 屏 | 内容 | 什么时候出现 |
| --- | --- | --- |
| 连接 | 地址、口令、"测试并保存"（拿一次 `periods/now` 当验收）、"只保存，先不测"；做成封面页 | 没配过时；之后只在 401 时回来 |
| 待办 | 顶部单行录入（右侧加图标）、前五条（勾选框 + 正文 + 删除图标 + 拖拽把手）、"展开其余 N 条"、已完成区 | 主屏第一个 tab（打开默认落点） |
| 记录 | 最新在前、关键词过滤（`q`）、点条目进编辑、底部固定"记一条" | 主屏第二个 tab |
| 编辑 | 多行输入、`n/上限` 计数、保存；已有条目带删除图标（连点两次才删） | 新建与修改共用一屏，整块替换主屏 |
| 报表 | 周/月切换、周期列表（含 `status`）、单份正文、生成按钮、刷新图标、复制到剪贴板（复制后有确认反馈） | 主屏第三个 tab |
| 更新 | 本机版本 → 服务端版本、大小、更新说明、下载按钮与进度、跳过这次、去开系统开关 | 点主屏那行提醒进来，不是 tab |

报头不放"改口令 / 改地址"入口（需求方 2026-11-26 定：连上之后不再主动改）。连接页只在首次启动和 401 时出现；401 时清掉 KeyStore 里的口令与别名再回去。要主动换地址只能重装或清应用数据——地址本来就绑在证书里，换地址要重签证书并重装（ADR-0009）。

三条交互定论，不是建议：

1. **生成按钮点了就转圈到接口返回**。服务端是同步生成（ADR-0004），一次可能要 60s 预算加一次重试；客户端造一个假进度或轮询状态，只会把"服务端正在等模型"这件事藏起来。
2. **进行中的本周/本月也能点生成**（FR-06），界面显示服务端给的 `source_count` 与 `generated_at`，不自己算"截至哪天"。
3. **failed 必须把 `fail_reason` 显示出来**（FR-05 不静默缺失）。`pending`/`running` 在单份响应里出现时显示"进行中"，不许显示成空白正文。

### 待办屏的五条定论

1. **前五在屏、其余折叠，靠展开而不是滚动**（FR-09）。折叠按钮上写清还有几条："展开其余 7 条"。展开是一次本地状态翻转，不发请求——`GET /v1/tasks` 本来就一次给全量（memo-and-report §5.1）。
2. **勾一下就完成，立刻离开前五**，已完成项沉进底部「已完成」区，第 6 名自动顶进前五（ADR-0014）。这是本地先行：先改内存里那份列表，再把 `{done:true}` 发出去；写失败就回滚并显示服务端原文，不能让一次抖动把勾选框卡在错的状态上。
3. **拖拽只在把手上起手势，整列一次提交**（FR-10）。把手吃掉竖直拖动，列表本身的滚动不受影响——两个手势抢同一个方向是这个屏最容易做坏的地方。拖动过程中只改本地顺序（乐观），松手发一次 `POST /v1/tasks/reorder` 带全部未完成 id；失败回滚到拖前顺序并提示，不做半程重试。
4. **前五之外也能拖**：展开之后拖拽作用于整个未完成序列，不是只在前五里换位。"只能调前五"会让第 6 名永远升不上来，那条限制没有任何需求支撑。
5. **录入走屏顶单行框，回车即加**，不进整屏编辑器。待办是一句话（ADR-0014 的边界），为它开一屏违反"两次点击内进键盘"；记录仍然走 `EditorScreen`，两边不共用。

### 更新页的四条定论

1. **提醒只是主屏报头下方一行字，不是弹窗**（ADR-0015）。进主屏查一次 `GET /v1/app/release`，`version_code` 比内置的高才出现；点进去才看到大小、说明和按钮。"打开就弹一屏"违反"两次点击内进键盘"。"这次不提醒"记在 `skipped_version_code` 里，只对那一个版本号闭嘴，发了更新的版本号它自己会重新开口。服务端一个版都没发过（404 `not_released`）时这行字根本不出现，不算错误也不提示"检查失败"。
2. **下载就在 App 进程里跑完，不起前台服务、不挂通知栏进度**。包是 10 MB 量级（估算），一条流写到缓存目录就交出去；服务换来的只是"切到别的应用还能看进度"，代价是常驻通知和一个权限——而那段时间用户其实正在等安装页。
3. **安装那一下不由 App 做**：只把 `FileProvider` 的 content URI 交给 `ACTION_VIEW`，确认框归系统。跳之前先问 `canRequestPackageInstalls()`，没允许就把人送到那个开关前面——Android 8 起按来源逐个授权，硬跳安装页只会得到一句"For your security…"，还回不到我们的界面。开关开完回来点"接着装"，包还在缓存里，不重下。
4. **进度按已下字节 / `Content-Length` 算，1 秒刷一次**；写完之后拿文件实际字节数和清单里的 `size`（服务端 stat 出来的，不是发布时手填）比对，不符就报"下完了但大小不对"，绝不把半包交给安装页——那只会换来一句看不出所以然的解析失败。

## 视觉

方向「编辑部案头」定于 [ADR-0013](../decisions/0013-editorial-desk-visual.md)：记录是原稿，报表是付印清样。实现集中在 `Theme.kt`（色板、字阶）与 `Components.kt`（共用元件），Screen 只做组装。

| 元素 | 取值 | 用途 |
| --- | --- | --- |
| 纸色 | `#F3F3ED` | 全局背景，铺满状态栏与导航栏 |
| 墨色 / 次级墨 | `#1B1C18` / `#5F6257` | 标题、正文 / 日期、说明、占位 |
| 分隔线 | `#CACBBF` | 1dp 发丝线：条目之间、段落之间 |
| 朱红 | `#B23A2D` | 唯一强调色：状态印章、选中下划线、光标、主动作、页边线 |
| 正文 / 界面字 | 系统衬线 / 系统无衬线 | 记录与报表正文、大标题 / 按钮、标签、日期、状态；数字统一 tnum |
| 圆角 | 2dp | 所有元件；不用卡片，不用阴影 |

- **分层靠线，不靠盒子**：2dp 墨色通栏线分大区块（报头、页眉），1dp 发丝线分条目；列表不是卡片堆。
- **状态印章**：报表的 ready/failed 显示为朱红方框、其余墨色，旋转 -3°；状态文本变化时做一次轻微下按——全 App 唯一的非用户触发动效，别处不加过渡、不加骨架屏。
- **页边线**：编辑页一条 1dp 朱红竖线从页眉通到底部，正文从线右侧起排，模拟稿纸左边距。
- **系统栏**：edge-to-edge，系统栏透明、图标深色；`adjustResize` 避让键盘，底栏动作始终在键盘之上。
- **勾选框是 18dp 方框，不用 Material 的 Checkbox**：2dp 墨色直角边、纸色底，勾上之后方框转朱、内部填一枚朱色对勾、正文换 `InkSoft` 并加删除线。它和 `StatusStamp` 同一套语言——形状是方、角是 2dp、强调只有朱红。
- **拖拽把手是右侧三条短横**（`InkSoft`，非强调色）：待办的默认排序语义已经由前五/已完成表达清楚，不需要再显式标"1、2、3"。被拖的那行整体下移跟手、其余行不补动画，松手才落位——ADR-0013 说过别处不加过渡。
- **行内短动词是图标，不是文字**（ADR-0017）：加＝十字、刷新＝留 60° 缺口的圆弧压一枚三角头、删＝描边垃圾桶，全部自绘在 40dp 方形点击区里，字形 20dp、笔画约 1.8dp，跟输入线和发丝线同一套笔画；不用 material-icons 的实心字形。名称只在 `contentDescription` 里。静止态用墨色（删除用次级墨），禁用态次级墨 45% 不透明度，不加旋转或骨架动效——ADR-0013 说动效只归用户触发的那两处。
- **文案**：按钮动词与结果同名（"存"→已保存、"复制全文"→已复制）；错误说清发生了什么，不道歉、不卖萌。
- **更新复用现成版式**：主屏那行提醒是 `Notice`（与限速、错误同一种元件），更新页的进度条自绘成 2dp 方角墨色条而不用 Material 的 `LinearProgressIndicator`——圆角胶囊条放进这套纸色发丝线版面里，看着像另一个 App 塞进来一页。
- **启动图标是同一套语言的对外那一面**（[ADR-0018](../decisions/0018-launcher-icon-ink-mark.md)）：墨底 `#1B1C18` 上一枚纸色描边 M，最后一笔收进转 -3° 的朱色方印；自适应图标只有 anydpi-v26 那份矢量加一张单色层，没有各密度位图。

## 接口调用与错误显示

请求形状、字段、状态码以 [memo-and-report.md §5](memo-and-report.md) 为准，这里只定客户端拿到每种错误时干什么：

| 情况 | 界面动作 |
| --- | --- |
| `401 unauthorized` | 提示"口令不对"，跳连接页，丢掉内存里的口令。不自动重试——重试只会喂限速计数 |
| `429 rate_limited` | 提示"试太快，N 秒后再试"，N 取 `Retry-After`，期间按钮禁用 |
| `400 bad_request` | 直接显示服务端 `message`（本来就写成人话，如"before 要 RFC3339"） |
| `404 not_found` | "这条已经不在了"，从列表移除该条 |
| `404 not_generated` | 空态 + 生成按钮，不算错误 |
| `404 not_released` | 更新通道：一个版都没发过，主屏那行提醒不出现。静默，不许显示成"检查更新失败" |
| `500 release_bad` | 更新通道：清单在而包不在（发了一半），说"服务端只发布了清单"——这条得区别于连不上 |
| `409 no_records` | "这个周期一条记录都没有"，显示成空态而不是错误 |
| `413 too_large` | 正常路径不该出现（客户端先挡），真收到就把服务端原文显示出来 |
| `502 generation_failed` | 显示响应里那条 `report.fail_reason` |
| `503 llm_not_configured` | "服务端没配模型"——这句话要区别于"模型出错"，否则用户会去查自己网不好 |
| `5xx` / `internal` | "服务端出错了"，附 `code` |
| `IOException`（连不上、超时） | "连不上服务器"，附当前地址；这是唯一该提示检查网络的分支 |
| `SSLHandshakeException` / `SSLPeerUnverifiedException` | "证书与地址不匹配，或打进来的证书不是这个环境的"——见 §6，这条几乎总是 flavor 与证书配错了 |

超时：连接 15s，读取 90s。读取必须**大于**服务端单次生成的 60s 预算加一次重试余量，否则客户端先断开、用户看到"连不上"，而报表其实正在库里落地——那是最容易被误判成产品坏了的组合。下载 APK 走同一个客户端：OkHttp 的读取超时算的是**两次读之间**的间隔，不是整包耗时，所以 10 MB 慢慢下也不会被这条 90s 掐断。

## 结构细节：周期从哪来

报表接口要 `period_start`，客户端手上没有这个值，而"算周一"这件事**不许在 Kotlin 里再写一遍**：那条规则一旦有两份实现，改口径就要改两处，而客户端那份没有任何测试能发现它跟服务端不一致，`make smoke` 也测不到它。

所以 `GET /v1/periods/now`（见 memo-and-report §5）返回当前周与月的起止日，报表页启动时取一次，"生成本周"直接拿 `week_start` 调生成。客户端拿到什么就用什么，绝不解释、绝不推算。

## 6. 构建环境与证书

两个 flavor（`local`、`server`），同一份源码，差的只有两样东西：

| | `local` | `server` |
| --- | --- | --- |
| 默认地址 | 模拟器访问宿主机的固定别名地址（`10.0.2.2` 那个），配 Windows 上跑的 `memora.exe` | 空串，必须在连接页手填——公网地址因此既不进仓库也不进 APK |
| 打进包的证书 | 只覆盖模拟器别名与回环地址那张，**进仓库**：值本身不含任何机器标识，换来"clone 完就能编译"，对应私钥不在仓库里 | 服务器上那张（SAN 是实际地址），只被拷进 `res/raw/`，永不进仓库 |
| 产物 | `app-local-debug.apk`，只进模拟器 | `app-server-release.apk`，装手机并当作发版的那个包 |

签名不属于 flavor 差异，四个变体（`local`/`server` × `debug`/`release`）共用仓库外的同一把 `~/.android/memora.keystore`（别名 `memora`，口令写在用户级 `~/.gradle/gradle.properties`，都不进仓库）：覆盖安装的前提是签名一致，用 AGP 默认的 debug key 签其中一个，以后换构建类型就得先卸载一次——等于把 ADR-0015 那条更新通道废掉一半。keystore 不在时构建照走 AGP 默认签名，为的是别人 clone 完还能编译。

模拟器不必非得连本机服务端：它和真机一样能出网，`serverDebug` 填云机地址就是同一条链路，差别只在打进包的那张证书（构建步骤见仓库 `android/README.md`）。

锁定方式是**把服务端那张证书作为唯一信任锚**（`network_security_config.xml` 里 `trust-anchors` 只引用 `@raw/memora_server_cert`，不设 `debug-overrides`，代码里也没有忽略证书的开关）。选它而不是 SPKI 摘要锁定，理由很实际：漏拷证书文件时资源不存在 → **编译失败**；而摘要写法漏了照样能编译，只会在运行时永远握手失败，报错还不说人话。把错误从运行期推到编译期，是这套 flavor 设计里最值钱的一条。

配套要求：签证书时用 `MEMORA_PUBLIC_IP=<地址1,地址2>` 传多个地址（`deploy/mkcert.sh` 支持逗号分隔，不带前缀按 IP 处理）。证书换了一定要重装 APK——这是 ADR-0009 明写的付出，客户端侧不做任何绕过。

## 边界与异常

- **正文为空或全空白**：不发请求，保存按钮置灰（服务端回 400，但没必要跑一趟）。
- **长度上限**：客户端按 2000 先挡并计数，**数的是码点数**——服务端那份是 `utf8.RuneCountInString`，按 UTF-16 长度算的话带表情符号的记录会被客户端提前挡下。真超限服务端回 413 不静默截断。两处都有这个数字是有意的取舍，见未决问题。
- **进程被杀**：输入变化后去抖 400ms 写草稿，重进编辑页先回填草稿；回填没完成前输入框不留给用户打字，否则那几个字会被后到的草稿盖掉。
- **删除**：连点两次才发请求（这个图标和"取消"挨着，误触代价是丢一条只有手机上记得的想法）。第一次点只给垃圾桶盖一枚 1.5dp 朱色方框、字形转朱，不换文字——文字版那条"确认删"会把整行的正文与拖拽把手左右挤歪（ADR-0017）；成功回 204；已删除再删回 404，界面按"已经不在了"处理，不报错。
- **时间显示**：服务端给的是 UTC 时间戳，界面按手机时区格式化。**周期一律用服务端返回的 `week_start`/`month_start`**，不用手机日历推。
- **并发**：同一时刻只允许一个生成请求在飞（按钮禁用），服务端另有周期级互斥。
- **列表分页**：`limit=200`（服务端上限）加 `before` 游标翻页，不做本地缓存；上一页没满 200 条就收起"更早的"，到底了还亮着按钮，用户会当成网络问题。
- **刷新只剩报表页一枚图标**（[ADR-0019](../decisions/0019-refresh-only-on-reports.md)）：记录页与待办页的"重新拉一次"发生在进屏时——切页签会重进组合、`LaunchedEffect` 自然重拉，从编辑页返回同理，写操作失败则自动回滚重拉；报表页保留图标，是因为服务端定时归档会在用户盯着这一屏时改掉周期列表。代价摆明：另一台设备刚记的那条，在记录/待办页要切走页签再回来才看得见，且没有提示；加载失败后在同一屏也没有重试按钮。没有下拉刷新（material3 里还是实验 API），也没有推送。
- **更新下载中途断掉**：写 `app.apk.part`，写完才改名，所以半包永远不可能被交给安装页；重进更新页从 0 重下而不是续传——服务端支持 Range，但客户端要接续就得另存偏移并校验，10 MB 量级下这笔状态机不值得写（估算）。

## 验收

分两级，各自验到什么要写清，别混着报：

1. **模拟器级**（`local` flavor + Windows 上 `memora.exe`）：记录增删改查、搜索、超限行文、口令错误与限速、报表生成与复制、failed 显示原因；待办加/勾/展开/拖拽四件事，且拖完点刷新看到的还是新顺序（证明 rank 落在服务端而非内存）；更新链路四步——提醒行、更新页、下载进度、系统安装页被真正拉起。这一级出不了门——它不碰公网，也证明不了手机能连上服务器。
2. **手机级**（`server flavor` + 服务器）：FR-01"两台设备看到同一条"、蜂窝网可达（要安全组入站规则已加）、真 DeepSeek 返回的报表质量、首次更新那一页"允许安装未知应用"的引导在真机厂商 ROM 上是否还成立。

工程可编译可运行（Windows 实测）：`./gradlew :app:assembleLocalDebug` 出 APK，模拟器经 `10.0.2.2` 连上本机 `memora.exe`，记录增删改查、搜索、超限、报表生成与复制都点过。待办四件事在同一条链上点过：屏顶录入 → `POST /v1/tasks` 201 落队首；勾一条 → 它沉进已完成区、第 6 名顶进前五、`PATCH` 200；"下面还有 N 条"展开与收起；拖把手把第 1 条拖下去 → `POST /v1/tasks/reorder` 200，**切走页签再切回来还是新顺序**（重进即重拉，名次确实落在服务端）。报表这一轮仍用假模型，界面上"用了 3 条记录" = 2 条记录 + 1 条本周勾掉的待办，FR-11 在客户端这一侧也对上了。

更新链路在模拟器上过了一遍：本机 `memora.exe` 配 `MEMORA_RELEASE_DIR`，拷进 `release.json`（`version_code=99`）与那份 APK，进主屏出"有新版 v0.9 测试（9.7 MB）可更新"，点进去显示"本机 v0.2 → v0.9 测试，约 9.7 MB"与说明，下载走到 44% 时进度行实时刷，写完 logcat 里能看到 `ACTION_VIEW` 把 `content://…fileprovider/…` 交给了 `com.google.android.packageinstaller`，校验结果 Pass。收口那一步用 `adb install -r` 覆盖旧包验的（签名一致才装得上，这正是那把共用 keystore 换来的）。**没验的**：`versionCode` 自己涨 1 之后回到 App 的"刚装好"那一屏；以及公网上的真实发版（服务器目录至今没放包，故意的——放了那行提醒就会开始唠叨需求方的手机）。`serverDebug`/`serverRelease` 要能编译，前提是需求方把服务器那张证书拷进 `res/raw/`——仓库里没有它，fresh clone 上这一步按设计就该失败，那本身就是 ADR-0009 那条防线的验证。
